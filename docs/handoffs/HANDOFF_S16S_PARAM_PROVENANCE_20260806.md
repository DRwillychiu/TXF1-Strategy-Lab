## 2. 方法論：先問「該不該存在」，再問「該設多少」

兩個測試都不是掃最佳值，而是**先測這個參數有沒有在做事**。

| 參數 | 先問的問題 | 讓它失效的設定 |
|---|---|---|
| `Struct_Trigger_Pct` | 這個閘門是多餘的嗎？ | 設 **0**（門檻取消） |
| `Trail_Giveback_Pct` | 這個基準還有在作用嗎？ | 設 **95**（幾乎不保護） |

**若結果與現值逐筆相同，該參數即為死參數，應移除而非調整。**
移除比調整更有價值——少一個要維護、要辯護、可能被誤調的東西。

## 3. 參數一：`Struct_Trigger_Pct`

### 3.1 它做什麼

結構停利腿的武裝門檻。峰值獲利未達進場價的 1.20% 之前，這條腿完全不運作。

### 3.2 1.20 的來源（程式碼原文）

```
Struct_Trigger_Pct : peak profit pct to arm, held at 1.20 for the
  first pass to keep the sweep two-dimensional. Unswept.
```

**為了讓 A2 的掃描維持二維（回看根數 × 緩衝點數），直接複製百分比腿的值。**
當時已標註為暫定，但後續直接進入 B1，未回頭處理。

對照：百分比腿的 1.20 來自 42 組窮舉掃描，且是為穩健性而選（1.0/60 分數更高但在懸崖邊）。
**兩個 1.20 來源完全不同，一個有證據，一個沒有。**

### 3.3 懷疑：這個閘門可能是多餘的

結構鎖利公式本身自帶閘門：

```
鎖利 = 進場價 − ( 最近 N 根最高收盤 + 20 )
```

進場初期，最近最高收盤就在進場價附近，**算出來是負的或極小**，
贏不過保本的 10 點，因此不會綁定。

**所以已經有兩道閘門：人為的 1.20%，與公式自帶的結構性閘門。**

### 3.4 掃描設定

| 參數 | 設定 |
|---|---|
| **`Struct_Trigger_Pct`** | **起 0.00　迄 2.00　間隔 0.20**（11 格） |

其餘全部維持 v1.14.0 現行值，一個都不要動：

```
Trail_On            true        Struct_On           true
Trail_Trigger_Pct   1.20        Struct_Lookback     20
Trail_Giveback_Pct  80          Struct_Buffer_Pts   20
Tier2_On            true        Struct_UseClose     true
Tier2_Trigger_Pct   2.00        M8_On               true
Tier2_Giveback_Pct  40          MaxHoldingBars      24
BE_Trigger_Pct      0.80        BE_Cost_Pts         10
```

**內建錨點：`1.20` 那一格必須跑出 129 筆 / 2,670,800 / 獲利因子 1.802717。**
跑不出來代表其他參數被動過，先修再看結果。

### 3.5 三種結果的處置

| `0.00` 的結果 | 意義 | 後續 |
|---|---|---|
| 與 1.20 **逐筆位元相同** | 門檻多餘，公式自帶閘門已足夠 | **移除該參數**，出場端降為八個 |
| 有差異但更差 | 門檻確實在擋早期誤觸發 | 記錄 1.20 的依據，收案 |
| 有差異且更好 | 門檻設太高，擋掉機會 | 依高原位置調整，走完九條驗收 |

### 3.6 預先登記的預期（事後不得修改）

1. **`0.00` 到約 `0.60` 之間的格子結果相同** —— 因為鎖利公式自帶閘門，早期算出來是負值
2. **`1.40` 以上結構停利出場由 1 筆降為 0 筆**，趨近於結構腿關閉
3. 整體差異規模 **2~5 筆交易、20,000 ~ 80,000**。這是參數微調非機制創新
4. **若 `0.00` 明顯優於 1.20，應懷疑而非高興** —— 那代表早期綁定的結構停損在幫忙，
   與「結構停利保護大獲利」的設計意圖不符，需逐筆查證是否砍到了什麼

### 3.7 省事版

若只想回答主要問題，**只跑 `0.00` 與 `1.20` 兩次**即可。

## 4. 參數二：`Trail_Giveback_Pct`

### 4.1 它現在管的範圍比看起來窄

B1 上線後，80 這個值**只在一個區間有效**：

```
峰值 1.2% ~ 2.0%   →  准吐 80%   ← 本參數
峰值 > 2.0%        →  准吐 40%   ← B1 分層接管
```

進場 45,000 換算，該段為峰值 540 ~ 900 點，留兩成 = 留 108 ~ 180 點。

### 4.2 三個重新檢視的理由

**一、80 是在「它是唯一保護」的時代掃出來的**
v1.12.0 的 42 組掃描時無結構腿、無分層，移動停利是保本之上唯一的機制。
現在它有兩個同事：結構腿管「前高很近」的，分層管「峰值很大」的。

**二、B1 掃描時把 80 釘住當基準，從未一起檢驗**
B1 是二維掃描（`Tier2_Trigger_Pct` × `Tier2_Giveback_Pct`），基準 80 固定不動。
三維掃描從沒做過，**而且不該做**——21 筆武裝交易撐不起三維搜尋。
所以 80 是繼承來的，非在分層架構下驗證過的。

**三、這一段的交易性質最微妙**
峰值 1.2~2.0% 是「有跑起來但沒跑很遠」的交易。
既非廢單（那些在第 4 根被快速停損砍了），也非大贏家。
保護太緊會砍掉可能繼續跑的，太鬆等於沒保護。

### 4.3 懷疑：80 可能幾乎沒在作用

v1.14.0 的 4 筆移動停利出場（#8、#9、#10、#23），已查證其中兩筆：

| 交易 | 峰值 | 落在哪一段 |
|---|---|---|
| #8 | 3.21% | **>2%，由分層的 40 管** |
| #23 | 3.54% | **>2%，由分層的 40 管** |

**若 4 筆出場全部落在分層區間，80 在實際出場上一次都沒用到。**

> ⚠️ #9 與 #10 的峰值百分比**尚未查證**。這一段是推論不是結論。
