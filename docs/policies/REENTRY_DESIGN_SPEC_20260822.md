## 0. 定義（使用者 2026-08-13 表述，為本規格的唯一定義）

二次進場成立需要**三個條件同時成立**：

1. **一次進場的條件仍然成立**（論點未失效）
2. **部位已因停損出場**（出場價在進場價的不利側）
3. **價格從停損價位回到一次進場價位**

→ 在**同一個價位**、用**同樣的口數**重新建立部位。

延伸表述：

> **進場邏輯條件確認，二次進場採用原始條件，然後重複做，
> 直到一次進場的條件區間結束。**

---

## 1. 核心邏輯：為什麼這個機制存在

**出場層的失效條件，與進場層的失效條件不同源。**

停損管的是「這一筆部位的風險」；進場條件管的是「這個方向的論點」。兩者不同步，
必然出現「論點還在、部位沒了」的空窗。二次進場填的就是這個空窗。

因此二次進場**不是一筆新交易，是同一筆交易被打斷後續上**。這句話是本規格所有
推論的來源：

| 推論 | 內容 |
|---|---|
| **R-A** | 風險參數必須**繼承**，不得重算（同一筆交易 = 同一組參數） |
| **R-B** | 出場端**不得分岔**（同一筆交易不會有兩套出場語意） |
| **R-C** | 鏈**沒有自然上限**（被洗出 N 次就該進 N 次） |
| **R-D** | 停利**參數**不變，但停利**狀態**歸零（峰值已被吐回，那段行情等於沒發生） |

## 2. 通用契約（每支策略都必須滿足）

### 2.1 三段式狀態機，順序不可更動

```
(1) 武裝  ：無條件，只看「前一根有部位、這一根空手」
(2) 解除  ：論點失效（結構條件轉為 false）
(3) 新週期：主訊號再現 -> 強制解除，主進場優先
```

**⚠ 順序是正確性的一部分。** 主進場與二次進場的互斥**完全靠**「狀態機排在進場區塊
之前」，沒有任何顯式旗標保護。把武裝區塊移到進場區塊之後，同一根 K 會立刻出現
兩張進場單。

### 2.2 事件版 vs 狀態版

主進場常是**離散事件**（穿越、交叉），該事件下一根就 false。二次進場的閘門必須用
它的**持續狀態版本**：

| 角色 | 用途 |
|---|---|
| 事件版 | 開啟新週期（狀態機第 3 段） |
| 狀態版 | 維持武裝（第 2 段）與進場閘門 |

### 2.3 觸發範圍：只有停損出場才武裝

| 出場類別 | 是否武裝 |
|---|---|
| 停損（出場價在不利側） | ✅ |
| 停利／移動停利獲利側出場 | ❌ |
| **Priority-0**（Kill／Registry／Holiday／Settlement） | ❌ **且必須主動封鎖** |

> **Priority-0 的洞**：S16_S 現行實作在被強制平倉後**仍會重新武裝**，狀態可跨整個
> 假日存活，禁令解除後用數日前的舊價位進場。新實作**不得沿用此行為**。

### 2.4 除法守衛

任何以「進場當下距離」為分母的比值，**必須守衛分母 <= 0**。失效方向為
**不武裝**（符合 R-1 fail-safe）。

### 2.5 開關全部使用數值 0/1

**不可使用 `TrueFalse` input。** MC12 最佳化器**完全不列出**布林 input，
掃描清單裡看不到，等於無法 A/B。一律宣告為數值，再鏡射成布林使用。

閘門一律寫成 `( Switch = False or Cond )`——全開時化簡為 `Cond`，這是錨點可複現的
前提。

### 3.1 D4 的推導（趨勢強度的量法）

三種標準化的免疫力：

| 寫法 | 位階免疫 | 波動免疫 | 判定 |
|---|---|---|---|
| 點數 `Close - MA >= X 點` | ❌ | ❌ | **否決**。即 MinSlope 的失敗模式：28 點在 2019 是 0.28%、2026 是 0.062% |
| 百分比 `(Close - MA)/Close >= p%` | ✅ | ❌ | 只解一半 |
| ATR 倍數 `(Close - MA)/ATR >= k` | ✅ | ✅ | 兩者皆免疫，但**押注在一個 ATR 估計值上** |

**採用的形式**：把百分比比值推到底，ATR 會自己消失。因為二次進場是在**原進場價**
評估（`Close = Entry`），百分比裡的價格項直接約分：

```
乖離%_now / 乖離%_entry
  = [ (Close - MA_now)/Close ] / [ (Entry - MA_entry)/Entry ]
  = ( Entry - MA_now ) / ( Entry - MA_entry )        <- Close = Entry，價格項約掉
```

**得到一個純距離比值**：

```
v_TrendRatio = ( Close - MA_now ) / v_Frozen_Gap
v_Frozen_Gap = Entry_P - MA_entry        { 進場當下凍結 }
```

| 性質 | 說明 |
|---|---|
| 位階免疫 | 兩個距離在同一價位取值，比值無因次 |
| 波動免疫 | 式子裡**沒有波動率項**，不存在估錯 |
| 零估計誤差 | 不需要儲存或相信任何 ATR 快照 |
| 自我校準 | 分母是這筆交易**實際**拿到的乖離，自動吸收進場滑移 |

**物理意義一句話**：均線已經吃掉原始乖離的多少比例。進場當下恆等於 **1.00**。

**為什麼不需要再做一次波動率調整**：進場條件本身已經隨波動率縮放
（L1 的 `Breakout_Level = maBase + ATR x 2`）。能走到「有部位可被停損」這一步，
波動率調整已經發生過。雙重標準化會讓 sweep 出來的數字失去可解讀性。

### 5.2 ⚠ 幾何複查（這一步不能省）

我最初提的狀態條件是 `Close > v_Frozen_Breakout`，**幾何上會讓機制永不觸發**：

```
進場價          Entry
凍結突破線      ~ Entry            <- 幾乎貼著進場價
凍結停損        ~ Entry - 120      <- ATR45=100 時
maBase (MA61)   ~ Entry - 200
```

停損打到時 `Close ~ Entry - 120`，**早已跌破 Entry 附近的突破線** -> 武裝在被停損的
同一時間解除，活不到價格回來。

**改用 `v_TrendRatio <= 0`（等價於 `Close <= maBase`，約 Entry - 200）**，
停損位置仍在解除線之上，武裝存活。

**通則**：突破帶是**觸發器**，不是**結構**。狀態條件要錨在均線／箱體本身，
不是錨在進場觸發價。移植到其他策略時必須重做這個幾何複查。

### 5.3 ⚠ Step 1 刻意不做的兩件事

**不加 `ExitFired`。** L1 目前確實可能同根送出兩張全倉市價單
（`Manual_Kill_Switch` 寫在 else-if 鏈外且排最後）。加互斥鏈會**改變行為**，
錨點就不可能零差異。那是 J-3，走自己的錨點。

**停損繼承邏輯寫入但不啟用。** 整段包在 `v_IsReEntry = True` 內；
