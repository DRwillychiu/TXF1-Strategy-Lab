# 驗證 SOP（v1，2026-09-23）

> 一句話：**每個 task 先過驗證再 commit；紅燈就停，列問題＋三個解法，由 Willy 選。**

## 1. 每個 task 的流程

```
開發 ──► verify.bat ──► 全綠 ──► 更新紀錄（登記簿／PROGRESS）──► commit
              │
              └─ 紅燈 ──► 停 ──► Claude 列「問題＋三個解法」──► Willy 選 ──► 修 ──► 重跑
```
- phase ＝ branch，task ＝ commit；每完成一個 Task 就在 `PROGRESS.md` 打勾，勾選與程式同一個 commit
- 任一步出狀況就停，不跳步
- Tier 1（進出場、停損、風控、下單防呆、部署）每個 Task 完成後暫停，等 Willy 審查

## 2. 五道關卡

| 關卡 | 檢查什麼 | 何時跑 | 狀態 |
|---|---|---|---|
| **G1 靜態** | .pla 純 ASCII、結算日平倉（出場＋進場閘門）、停損三件套（SetStopContract→SetStopLoss＋SL_Pct）、進場需空手、回看長度 ≤ 99、無佔位／無效 Block 旗標 | 每個 task commit 前 | ✅ 已建（`tools/verify_static.py`） |
| G2 單元 | 規則層純函式（連虧暫停、日週上限）的 pytest | Python 版上線後 | ⏸ 待 Python 規則層 |
| **G3 回測基準** | 新報告 vs 核准基準：開始日、滑價、本金、週期、參數；共同期間逐筆交易完全一致 | 任何回測後、phase 結束前 | ✅ 已建（`tools/verify_baseline.py`） |
| G4 券商 UAT | 測試環境：下單／改單／刪單／查詢；部位對帳 | 上線前、盤中手動 | ⏸ 需測試帳號 |
| G5 設定快照 | MC 圖表 Data1/2/3、交易時段 | 回測前 | ◑ 開始日／滑價／本金／週期已由 G3 比對；Data2/3 仍需人工 |

## 3. 踩坑 → 檢查（回歸規則）
- 每個問題結案時，**必須新增一條檢查**，並在登記簿註明檢查編號

| 踩過的坑 | 對應檢查 |
|---|---|
| 停損沒有上限（7/13） | G1-C3 停損三件套 |
| 圖表設定不同、回測對不上（L4 v14.7） | G3 設定＋逐筆比對 |
| 6/25 訊號重複、多開反向單 | G4 部位對帳（待建） |

## 4. 基準的管理
- 只有 Willy 核准的回測版本，才能用 `tools/make_baseline.py` 產生／更新基準
- 基準更新要單獨 commit，訊息寫明原因

## 5. 紀錄檔維護（每週一次）
- 盤查 .md：已定案的新版本取代舊內容
- 被取代的內容移到同名 `*_archive.md`，主檔只留現行版本

## 6. 分工
- Claude：寫檢查腳本、產基準、紅燈時列問題＋三個解法
- Willy：在 Windows 跑 `verify.bat`、把結果貼回、選解法
