### 3.3 為什麼 Settlement 出場勝率 100%

L1 進場條件嚴格（60M ATR + 趨勢過濾）→ 進場後若虧損，SL 早就出場了。能撐到結算日的部位 = **已經朝對的方向走了好幾天的高品質趨勢**。Settlement_Flat 在「正在賺錢」的部位上強制平倉 = **鎖利**。

換言之：Settlement_Flat 對 L1 不只是「結算日危險強制平倉」，更是**「強制鎖利點」**。

### 3.4 沒有 Settlement_Flat 會發生什麼

若無 Settlement_Flat 模組：
1. **TXF1 連續合約跳價**：04/15 13:30 後 data feed 切到 05 月合約，價格 gap 觸發 SL 假信號
2. **結算前操縱波動**：12:30-13:30 大戶結算前部位調整，可能反向 spike 觸發 SL
3. **跨日 gap risk**：隔日 06 合約已失效，但策略還以為持有，部位混亂

**估算**：14 筆若都因上述原因損失 30%，整體損失 = 1,529,000 × 0.3 ≈ -459,000 NTD。
**結論**：Settlement_Flat 對 L1 是**+459k ~ +1,529k 範圍的獲利保護**。

## 四、L1 兩筆異常 00:00 進場深度檢視

### 4.1 異常明細

| 進場 | 出場（45 分鐘後）| P&L |
|------|----------------|-----|
| 2023-01-18 00:00 @15035 TL_Entry | 2023-01-18 00:45 @14986 TL_SL | -11,800 |
| 2023-02-15 00:00 @15732 TL_Entry | 2023-02-15 00:45 @15665 TL_SL | -15,400 |

### 4.2 為什麼能進場？理論上 v_Settlement_Day 應 = TRUE

**最可能解釋**：MC PowerLanguage 對「夜盤跨日 K 棒」的 `Date` 屬性處理。

期貨夜盤 15:00 ~ 05:00 在 MC 上通常會被歸屬於**下一個交易日**。但 60M chart 上某些 K 棒（如 23:00 ~ 00:00 那根）的 `Date` 屬性可能仍是前一天（週二）。

- MC report 顯示 trade 時間 = 2023-01-18 00:00:00（壁鐘時間）
- 但策略執行時 K 棒的 `Date` = 2023-01-17（週二）→ `DayOfWeek = 2` ≠ 3 → `v_Settlement_Day = FALSE` → Entry gate 通過

### 4.3 是否要修補？

**否**。理由：
1. 兩筆都在 45 分鐘內被 SL 止損出場，**沒有撐到 12:30 觸發 Settlement**
2. 總影響 = -27,200 NTD（相對 L1 淨利 2.27M 微不足道）
3. 真正的「白天時段」(08:45 ~ 13:45) 結算日進場 = 0 筆 ✓
4. 若改成「整個結算日 24 小時阻擋」，要解決 MC 的 Date 認定機制，複雜度高且回報低

**結論**：這是 MC 平台特性，不是模組設計問題。**監控但不修補**。
