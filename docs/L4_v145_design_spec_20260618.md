## 一、改進設計（A + B 雙模組）

### Filter A：Daily MA Gap% 強多頭過濾

**目的**：當 Daily Fast MA 大幅領先 Slow MA（強多頭）時不允許做空

**邏輯**：
```powerlanguage
v_Daily_MA_Gap_Pct = (v_Daily_FastMA - v_Daily_SlowMA) / v_Daily_SlowMA * 100;
v_Strong_Long_Block = Strong_Long_Filter_On and
                      (v_Daily_MA_Gap_Pct >= Max_Gap_Pct_Allowed);
```

**新 inputs**：
- `Strong_Long_Filter_On(true)` — 開關，預設 ON
- `Max_Gap_Pct_Allowed(1.0)` — Daily Fast 領先 Slow 多少 % 時禁止做空

**加入進場條件**：
```powerlanguage
if MarketPosition = 0 and ... (原本 8 個 AND) and
   v_Strong_Long_Block = false then begin   { ★ A-Filter }
    SellShort ("CS_Entry") next bar at Market;
end;
```

**預期效果**：
- 強多頭結構（如 2024 H2）→ 過濾掉 50% 以上 CS_BreakExit 進場
- 不影響盤整、震盪、跌勢中的真正反轉訊號

### Filter B：Fast BreakExit（15M Close + ATR Buffer 提早觸發）

**目的**：當前 CS_BreakExit 用 60M Close 觸發 = 慢 1 根 60M K（最多 1 小時）

**邏輯**：
```powerlanguage
{ B: Fast BreakExit — 15M 級提早觸發 }
if Fast_BreakExit_On and MarketPosition < 0 and
   v_Locked_Top > 0 and
   Close > v_Locked_Top + v_Current_ATR * Fast_Exit_ATR_Buffer then begin
    BuyToCover ("CS_FastBreakExit") next bar at Market;
    ExitFired = 1;
end;
```

**新 inputs**：
- `Fast_BreakExit_On(true)` — 開關，預設 ON
- `Fast_Exit_ATR_Buffer(0.5)` — 突破 Box_Top + ATR × 0.5 即觸發

**位置**：放在 P0 Settlement 之後、P1 Disaster Control（CS_BreakExit）之前

**預期效果**：
- 從「60M Close 收盤確認 + Box 已破壞」→「15M Close 超越 Box_Top + 0.5 ATR」
- 提早 0-3 根 15M K 出場
- 平均虧損 -18,890 → 預估 -10,000 ~ -13,000
- 新標籤 `CS_FastBreakExit` 區隔追蹤

## 二、為什麼選 0.5 ATR Buffer（非 0 或 1.0）

| Buffer | 提早程度 | False trigger 風險 |
|--------|--------|----------------|
| 0 | 最快（觸到 Box_Top 就出）| **極高**（盤整波動經常觸及）|
| 0.3 | 快 | 中（小 false trigger）|
| **0.5** ✓ | **適中** | **低** |
| 1.0 | 慢（與原本 CS_BreakExit 接近）| 極低 |

**0.5 ATR 是平衡點**：足以區分「真突破」與「盤整噪訊」，又不會等到 60M 才出場。

---

## 三、為什麼選 Daily MA Gap% = 1.0（不是 0.5 或 2.0）

| Threshold | 過濾比例 | 風險 |
|-----------|--------|------|
| 0.5 | 過嚴（年化進場 13 → 5 筆）| 樣本太少 |
| **1.0** ✓ | **適中**（預估過濾 30-40%）| **平衡** |
| 2.0 | 過寬（極端多頭才阻擋）| 無實際過濾效果 |

**1.0% 落在 TXF 一般中強多頭結構**（如 2024 H2 / 2021 多數時段都會觸發）。

## 五、避免重蹈 RangeForceExit 覆轍

### 上次失敗原因
- `Time >= 1200` 沒上界 → 夜盤誤觸
- 沒先 MC 驗證歷史通過率 → 0 進場

### v14.5 如何避免
| 風險 | v14.5 對策 |
|------|---------|
| Time 24-hour 制陷阱 | **不涉及時段條件**（兩個 filter 都是 Daily MA / ATR 條件）|
| 過濾過度導致 0 進場 | **預設可關閉**（兩個 _On 設 false → 完全復刻 v14.4）|
| 改變既有 alpha | **不改既有邏輯**，只加新 gate / 新 exit |
| MC input persistence | **新 input 預設 ON 但需重載**（規範要求「完全移除→重載」）|
