# 零觸發路徑　逐一查證

> 2026-09-08。`tools/flow_check.py` 報出 10 個零觸發路徑，**全部逐一量測原因**。
>
> ```powershell
> python tools\flow_check.py "data\mc_export\TXF1 1 分鐘.txt"
> ```
> → **五支合計 0 個未查問題**

---

## 為什麼要查

**零觸發有三種可能，而它們的意義完全不同：**

```
○ 已知關閉    開關 = 0。設計如此
● 已查證      條件會成立，只是這段期間沒發生
▲ 有發單沒成交 掛了單但價位沒碰到
✗ 從未發出    **條件永遠不成立 ← L4 v18 的零觸發事故就是這一類**
```

L4 v18 的事故是：解除條件被停損本身蘊含，**旗標在設立的同一根就被清掉**。
那種缺陷不會有任何斷言失敗，只會表現成「0 次」。

**所以每一個 0 都必須有量測過的原因，否則就是把事故當正常。**

## 查證結果

### A　Settlement 類（4 個）　L2 · L4 · L5

| 策略 | 總筆數 | 跨越結算日 | 12:30 後仍持倉 |
|---|---|---|---|
| L2 | 92 | 4 | **0** |
| L4 | 94 | 2 | **0** |
| L5 | 240 | 4 | **0** |
| **L3** | 442 | 37 | **4** ← 有觸發 |

**是沒機會，不是條件壞掉。** L3 的 `CL_Settlement` 有 3 筆成交，
證明機制本身能運作。

> 結算日**整天封鎖進場**，所以只有前一天進場並持有過夜的部位才可能碰到。
> 而 L2/L4/L5 的持倉多在當日了結。

### B　`TS_WeeklyExit`（L2）★ 這個最值得看

**條件**：週五 + `Time == 1245` + 已存 ≥ 13 週 + 收盤 > 週線 SMA13

**逐根量測**：

```
符合「週五 + 1245」的 60M K 棒       357 根
其中持倉中                            16 根
且收盤在週線 SMA13 之上                0 根   ← 關鍵
實際發出                               0 次
```

**L2 是空單。收盤站上週線 SMA13 代表趨勢翻多——
而那種情況下，停損早在週五之前就先觸發了。**

> **這是機制間的競爭，不是缺陷。** 週線強制出場是最後防線，
> 而前面的停損從來沒讓它有機會啟動。

### C　`TL_SP_Gap`（L1）

**條件**：`Close < Final_Exit` 且 `Final_Exit >= EntryPrice`

```
TL_SL_Gap（虧損側跳空）   35 筆
TL_SP_Gap（獲利側跳空）    0 筆
```

**跳空分支本身會觸發 35 次，只是每次都落在虧損側。**

獲利側跳空需要「收盤跌破一個**高於進場價**的停損線」——
也就是 SP 鎖定生效後、45M 一根之內大幅回落。6.5 年零次。

> `TL_SP` 本身有 87 筆，所以 SP 鎖定機制運作正常。

### D　L5 的四個「有發單沒成交」

```
Bot 腿  59 筆   Mid 腿 181 筆   Mid 是 Bot 的 3.1 倍
分批出場僅 10 組 → Stage 2/3 只在這 10 次之後存在
```

| 標籤 | 需要同時成立的條件 |
|---|---|
| `BL_BE_Bot` / `BL_BE_Mid` | Stage 2/3 + 價格回到進場價 |
| `BL_Trail_Bot` | Bot 腿 + Stage 2/3 + 追蹤啟動 |
| `BL_Holiday_Bot` | Bot 腿 + 假日尾盤持倉 |

**全部是罕見條件相乘。** `BL_Trail_Mid` 有 4 筆，證明機制能觸發。

## 已寫進工具

十個原因登記在 `tools/flow_check.py` 的 `DIAGNOSED` 表。

**登記的意思是「已量測過為什麼是 0」，不是「忽略它」。**
下次跑會顯示 `●` 而不是 `✗`，而**新出現的零觸發仍然會是 `✗`**。

## 順帶修掉一個工具 bug

`tools/status.py` 的第 2 段（移植稽核）在你的機器上是空的並報「工具壞了」。

**根因**：`subprocess` 在 Windows 預設用 cp950 解碼子行程輸出，
吃不下 `✓` / `✗` / 中文，讀取時就拋 `UnicodeDecodeError`。

**而錯誤訊息看起來像「稽核工具壞了」，其實稽核工具是好的。**

已加 `encoding="utf-8"` 與 `PYTHONIOENCODING=utf-8`。
