### 兩個結論

**一、intrabar policy 對 L2 完全沒有影響。**

因為 L2 有 ExitFired，**一根只可能一張單，從來不會有兩張單競爭同一根**。
那個歧義只會影響 L3（TP limit + SL stop 並存）與 L5（雙腿）。

> **L2 正因為對這個歧義免疫，才是乾淨的測試床。**
> 它把「移植對不對」與「成交假設對不對」兩件事分開了。

**二、gap policy 有影響，而 `AT_OPEN` 較接近 MC。**

`at_trigger` 得出 3.45M，`at_open` 得出 3.00M，MC 是 2.67–2.88M。
**MC 用的是 AT_OPEN**（跳空時成交在開盤價，不是觸發價）。

## 過程中修掉的一個 bug

首次執行得出 **172 筆、出場標籤 100% 都是 `TS_TTP`**。
只有一種標籤，一定是錯的。

根因在 runner 的順序：在推進 K 棒**之後**才 `advance_bar()`，
所以進場那根的 `bars_since_entry` 已經是 1，策略永遠看不到 0。

連鎖後果：

```
S8   bars_since_entry == 0 才鎖初始停損
       → sl_trig 永遠 0 → 優先級 5、6 失效

S11  bars_since_entry == 0 才設 lowest_close
       → 停在 0.0
       → wave_profit = entry_price − 0 = 20000  → 閘門恆真
       → ttp_line = 0 × 1.015 = 0               → close > 0 恆真
       → TTP 在進場後第一根就開火
```

**一個排序錯誤解釋全部現象。** 修正後 172 → 92 筆、一種標籤 → 九種。

已寫成測試 `test_runner_ages_position_before_filling`。
