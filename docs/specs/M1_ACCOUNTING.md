## 二 帳務取樣點

### 規則

```
一般日   1345      日盤收盤
結算日   1330      近月合約停止交易
假日     不取樣    該交易日不存在
```

### 實測（141,302 根 15M，零例外）

```
結算日     92 天    末根戳記全部 1330      100%
一般日  1,771 天    末根戳記全部 1345      100%
連假       57 次    交易日自然不在清單中
帳務取樣棒 1,863 天  缺漏 0 天
```

**因為結算日的 1330 就是那天最後一根，
「取該交易日日盤最後一根」同時涵蓋兩種情況——不需要特判。**

### ★ 為什麼不能用夜盤末 05:00

TAIFEX 的每日結算在**日盤 13:45**，夜盤屬於**次一交易日**。

實測（五支合計，樣本內，單位：點）：

| 取樣方式 | MDD 點數 | 相對 | 序列長度 |
|---|---|---|---|
| ① 只算平倉 | 5,768 | 1.00x | 1,344 |
| ② 各支 Data1 收盤 | 6,436 | 1.12x | 36,520 |
| **③ 日結算 13:45** | **6,416** | **1.11x** | **2,068** |
| ④ 夜盤末 05:00 | 6,052 | 1.05x | 2,211 |
| ⑤ 各支 Data1 最差價 | 6,598 | 1.14x | 36,520 |

**④ 低估 5.7%**，因為把次日的行情算進了今天。

**③ 與 ② 只差 0.3%，但計算量少 94%。**

### 兩種日線必須分開

```
策略用的日線   各支不同（L5 用 NIGHT_FIRST，其餘 DAY_FIRST）
               → 策略「看到」的市場
帳務用的取樣   一律日盤最後一根
               → 帳戶「結算」的時點
```

## 三 兩條權益曲線

### 定義

```
③ 日結算    用該交易日日盤最後一根的收盤價     與券商對帳單同定義
⑤ 盤中極值  峰值取有利極值、谷底取不利極值     MC12 的 Intraday Peak to Valley
```

### ★ ⑤ 的算法，第一版寫錯了

**兩邊都用不利極值是錯的**——那會把峰值也壓低，回撤反而變小。

2026-09-08 第一版就犯了這個錯，實測 ⑤ 比 ③ 小，**而那不可能**。

正確：

```
equity_best   多單用 high、空單用 low     有利極值 → 找峰值
equity_worst  多單用 low、空單用 high     不利極值 → 找谷底

MDD⑤ = max over t of ( max(equity_best[0..t]) − equity_worst[t] )
```

**⑤ 必然 >= ③**，已寫成測試。

### 雙重濾網的價值

```
兩者的差距 = 盤中曾經穿越但收盤前收回來的部分

差距大 → 部位常在盤中被逼到極限但撐回來 → 追繳風險比對帳單高
差距小 → 收盤價已能代表風險 → 對帳單可信
```

**這個差距本身就是一個指標，而它只有兩條並列才看得出來。**

帳戶 A（多）L1 · L3 · L5   最大 6 口
帳戶 B（空）L2 · L4        最大 4 口

| 商品 | 點值 | 名目每支 | 帳戶 A | 帳戶 B | 總本金 | 可承受點數 |
|---|---|---|---|---|---|---|
| **TMF 微台** | 10 | 60,000 | 200,000 | 100,000 | **300,000** | 3,000 |
| MXF 小台 | 50 | 300,000 | 1,000,000 | 500,000 | 1,500,000 | 3,000 |

**`tools/equity.py` 預設微台**，`--instrument MXF|TXF` 切換。

> **名目分攤與帳戶配置刻意不一致**：帳戶 A 有 3 支但配 200,000
> （名目應為 180,000），帳戶 B 有 2 支卻只配 100,000（名目應為 120,000）。
> 理由：**多單出手機率高**。

### MDD 的三種分母

**同一組交易，三種分母三個答案。三個都報，各自標明。**

```
單支 MDD%   分母 = 名目每支 60,000
帳戶 MDD%   分母 = 200,000 或 100,000
總體 MDD%   分母 = 300,000
```

| L4 | 94 | 23.07% | 23.12% | 24.20% | 1.09% |

### 雙帳戶與總體

| | 本金 | ③ 日結算 | ⑤ 盤中極值 | 峰值口數 | ③ 金額 | 發生日 |
|---|---|---|---|---|---|---|
| **A 多** L1·L3·L5 | 200,000 | 12.30% | 12.40% | **6 / 6** | 36,288 | 2021-03-10 |
| **B 空** L2·L4 | 100,000 | **19.23%** | 19.23% | **4 / 4** | 49,855 | 2024-08-23 |
| **總體** | 300,000 | 8.53% | 8.60% | 6 | 36,288 | 2021-03-10 |

### ★ 分散效果的正確算法

**不用「各支 MDD 相加 vs 組合 MDD」。**

各支的 MDD 各自發生在不同日子，把五個不同日子的最壞值相加，
本來就不會等於任何一天的值——**那個差距大部分來自時點不同，不是分散效果**。

正確的證據是：**在總體 MDD 那一天，五支各自貢獻了多少。**

實測 2021-02-02（峰值日）→ 2021-03-10（谷底日），共 36 天：

| 策略 | 峰值日權益 | 谷底日權益 | 貢獻 |
|---|---|---|---|
| L1 | 117,315 | 104,813 | −12,502 |
| **L2** | 74,242 | 74,242 | **0**（空手） |
| L3 | 86,725 | 70,898 | −15,827 |
| **L4** | 76,278 | 76,278 | **0**（空手） |
| L5 | 71,042 | 63,083 | −7,959 |
| **合計** | | | **−36,288** |

**與總體回撤逐分吻合。**

> **三支多單全跌，兩支空單完全沒部位——那次回撤裡零分散效果。**
> 「多空互補」在這一刻沒有發生，**因為空單策略當時根本不在場**。

### ★ 兩件值得注意

**一、空單帳戶的 MDD 比多單帳戶高 7 個百分點**（19.23% vs 12.30%），
儘管它只有 2 支策略。**因為它的本金只有一半。**

**二、兩個帳戶的峰值都打到上限**（6/6 和 4/4 口）。
而當前保證金下，帳戶 A 滿倉需 210,300（105%）、帳戶 B 需 140,200（140%）——
**這在實戰中會被拒單**。已記錄，屬 M6 組合監控的範圍。

### ★ L2 的真實回撤是只算平倉的 2.2 倍

```
只算平倉    9.26%
日結算     20.56%
```

**L2 的浮虧遠大於已實現虧損**——它的部位長期抱著大額浮虧，
最後靠停利或停損了結，而**只算平倉完全看不到那段過程**。

### L3 與 L4 反而略降，那是對的

```
L3   28.22% → 27.97%
L4   15.20% → 14.68%
```

**含未平倉會同時抬高峰值。** 浮盈讓峰值變高，
而分母是滾動峰值，所以百分比可能下降。**這是定義的必然，不是 bug。**

## 六 組合合成

```
逐日相加變化量，不是各支曲線相加
```

**直接相加會把期初資金重複計算 N 次。** 已寫成測試。

而組合 MDD 的定義早已定案：

```
組合 MDD = 各支每日損益逐日相加 → 合成一條曲線 → 再做一次 MDD
         ≠ 各支 MDD 相加
```

## 八之二　金額跟著百分比走（裁決 2026-09-08，選項 A）

`drawdown.py` 原本把 `max_drawdown`（百分比）與 `max_drawdown_amount`（金額）
**獨立追蹤**，兩者可以發生在完全不同的時點。

實測（組合 ③ 曲線）：

```
最大百分比  14.84%      2021-03-10   金額   704,970
最大金額    1,290,274   2026-06-12   佔比     7.06%

相差 1,920 天、585,304 元
```

**固定口數下，權益成長後晚期的絕對金額必然更大——
所以「最大金額」衡量的是規模，不是風險。**

### 修正後

```
max_drawdown           百分比。MDD 的定義
max_drawdown_amount    **該百分比那一點的金額**
max_drawdown_index     發生的索引
peak_to_valley_amount  最大絕對金額（原行為，改名保留）
peak_to_valley_index   發生的索引
```

**不變量：`max_drawdown_amount == peak[i] − equity[i]`，
其中 `i = max_drawdown_index`。** 已寫成測試。

修正後的組合：

```
③ MDD 14.84% = 704,970　於 2021-03-10
⑤ MDD 14.97% = 711,770　於 2021-03-10
```

**同一天，且 ⑤ 在百分比與金額上同時大於 ③。**
