## ✗ H1 換月假象 —— **已排除**

**假設**：TXF1 連續近月在結算日 13:30 換月，人為跳空觸發了額外交易。

**跳空確實存在且很大**（92 個換月點實測）：

```
結算日 13:30 → 16:00   絕對值中位 60.5 點   標準差 141.1   最大 511
一般日 13:45 → 16:00   絕對值中位 11.0 點   標準差  57.1
```

**換月跳空是一般隔夜跳空的 5.5 倍。**

**但五支策略在結構上碰不到它。**

```
Settlement_Flat_Time = 1230   強制平倉在 12:30
換月點                 1330   近月停止交易
v_Settlement_Day       整個結算日封鎖進場
```

**12:30 < 13:30，而且整天不進場。** 實測 L2 / L4 全歷史：

| | L2 | L4 |
|---|---|---|
| 結算日進場 | **0** | **0** |
| 結算日 12:30 後才出場 | **0** | **0** |
| 真正跨越 13:30 換月點 | **0** | **0** |

> **這不是「觀察不到聚集」，是「結構上不可能」——更強的結論。**

### 我第一次的標記寫錯了

2026-09-06 用戶指出：「結算日當天夜盤跳空肯定有，也因此針對策略上，
完全沒有結算日當天留倉。」

我原本用 `span_days = 1` 的鄰近窗口，把**結算日的隔一天**也算成跨越換月，
誤標了兩筆與換月完全無關的交易：

```
L4  +192,359  2026-08-20  CS_TimeExit    ← 結算日隔天，不是跨越
L2   −84,891  2025-04-17  ENGINE_STOP    ← 同上
```

**已修正** `spans_rollover()` 為只認真正跨越 13:30 的，並寫成測試。

保留這個模組的理由：**它可能失敗而沒失敗。**
若日後有策略改掉 `Settlement_Flat_Time`，它會立刻回報非零。

## ✗ H5 對齊規則 —— **已排除（2026-09-07）**

我原本說「這需要逐筆 diff」。**那是錯的，可以直接測**——
把對齊做成可切換的，跑兩種規則看筆數。

| 對齊規則 | 筆數 | 淨利 | PF | 勝率 | 與 MC 79 的差 |
|---|---|---|---|---|---|
| **`closed_only`**（只暴露已收盤） | **83** | 1,399,503 | 1.9221 | 43.37% | **+4** |
| `include_forming`（含形成中的） | **44** | 915,170 | 3.7112 | 56.82% | **−35** |
| MC12 v14.6 | 79 | 877,200 | 1.4902 | 41.77% | 0 |

**寬鬆對齊讓筆數掉到 44，離 79 差 −35。保守對齊只差 +4。**

`include_forming` 之所以大幅減少交易，是因為讓策略讀到形成中的
Data2 K 棒後，箱體會被尚未確定的高低點污染，導致箱體更常被判定為失效。

**排除。我的保守對齊是對的。** 兩種規則都保留為可切換，因為
MC 的實際規則沒有文件——但證據強烈指向 `closed_only`。
