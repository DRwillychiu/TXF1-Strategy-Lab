## 一、L2 取消假日限制 — 機構角度的回答

### 用戶論點

> 「L2 是趨勢空頭，假日跳空多數會向下，L2 出場嚴謹可以躲開節日風險。」

### 機構角度檢驗

#### 1.1 假日跳空方向統計（**駁斥「多偏空」假設**）

**台股 / TXF1 重要假日後實際開盤跳空方向**：

| 假日類型 | 範例 | 跳空方向 |
|---------|------|---------|
| 2020 春節 | COVID 衝擊 | **-1,000 點以上**（極端向下）|
| 2020 端午 | 全球疫情 | 微跳空向下 |
| 2021 春節 | 量化寬鬆延續 | **大跳空向上** |
| 2021 端午 | — | 跳空向上 |
| 2022 春節 | 升息預期 | **跳空向下** |
| 2022 中秋 | 反彈 | **跳空向上** |
| 2023 春節 | 反彈延續 | 跳空向上 |
| 2024 春節 | 台積電 ADR 大漲 | **大跳空向上** |
| 2024 端午 | — | 跳空向下 |
| 2025 春節 | AI 行情高峰 | **大跳空向上** |
| **2025 端午** | 川普關稅前 | **跳空向上** |

**統計**：11 個樣本中 **6 向上 / 5 向下**

→ **沒有「多偏空」的統計依據**。
→ 跳空方向**完全取決於假期內全球事件**（美股表現、地緣政治、企業財報）。

#### 1.2 「多偏空」假設的 confirmation bias 來源

可能讓人誤以為偏空的原因：
- **記憶偏誤**：大跌印象深刻（COVID 2020、升息 2022）
- **存活者偏誤**：只記得做空賺到的，忘記做空被軋的
- **「機構出貨」迷思**：實際機構在大跳空後**多反向操作**（買低）

#### 1.3 機構為何幾乎全部假日前平倉

機構風險管理的 5 個鐵律：

##### 鐵律 1：Tail Risk 不可控

```
即使「假日跳空向下」機率 80%
單次反向跳空 -500 點 × 1 口 = -100,000 NTD
單次有利跳空 +200 點 × 1 口 = +40,000 NTD

期望值 = 0.8 × 40,000 - 0.2 × 100,000 = +12,000 NTD ✓
但：
  - 80% 賺 4 萬不顯眼
  - 20% 虧 10 萬會被通報
  - 客戶看到單筆 -10 萬會贖回
  - 機構 risk manager 寧可放棄 12,000 期望值
```

##### 鐵律 2：VaR / CVaR 法規約束

機構必須計算「99% VaR」與「Expected Shortfall (ES)」：
- 假日 gap 是 fat-tail 事件
- 統計上 5σ 級事件
- 不能用「平日波動」推算
- **法規要求假日風險獨立計算**

##### 鐵律 3：流動性中斷風險

假日後重新開盤可能：
- 漲跌停板鎖死（成交不了）
- 滑價極端（買賣價差 10-20 點）
- 熔斷（如 2020-03-13）

→ **計算 SL 時假設「即時成交」在這時破功**

##### 鐵律 4：保證金追繳

連假期間：
- 帳戶損失即使「未實現」也計算保證金
- 假日結算後（如下班週五）broker 可能週一強制平倉
- **個人帳戶比機構更脆弱**

##### 鐵律 5：心理壓力 + 操作錯誤

機構 PM 心理：
- 假日中無法看盤
- 假期間焦慮影響家庭
- **機構規定不允許「假日睡覺賭運氣」**

### 1.4 L2 出場是否真的「嚴謹到躲開假日」？

#### L2 的出場機制清單
```
Stop Loss      : 嚴謹（v_Stop_Level frozen at entry）
SP / BE        : 嚴謹（v14.2 經 A/B test 優化）
Holiday_Flat   : 03:00 強制平倉（已有）
Settlement_Flat: 12:30 強制平倉（已有）
ImmediateStop  : v14.4 P3b 已加 SetStopLoss
```

**但「嚴謹出場」**無法救「**假日中無法觸發**」的情境：
- 假日 6/19-6/21 整段不交易
- 6/22 開盤瞬間 **跳空 +500 點**
- SL 設在 +200 點 → 開盤直接觸發 → 但成交在 **+500 點**
- **多虧 -300 點是出場機制無法救的**

#### 真實案例：2020-03-13 熔斷
- 3/12 收盤後巨變
- 3/13 開盤瞬間跌 -1,000 點
- 任何 SL 都「跳空跨越」
- 即使是機構，**SL 滑價 -200~-400 點是常態**

### 1.5 機構建議：L2 假日限制必須**保留甚至加強**

| 改進方向 | 含義 |
|--------|------|
| **現狀**：HolidayFlat 03:00 | 凌晨平倉，已防裸露 |
| **建議**：保留現狀 | 跨假日 tail risk 不值得賭 |
| **可選優化**：連假前一天日盤 flat | 如 6/18 13:00 即平，比 6/19 03:00 更早 |
| **絕不建議**：取消 HolidayFlat | 違反機構標準 |

### 1.6 如果用戶堅持要試「假日空頭收割」

**唯一機構可接受的做法**：

```
新增策略 S99_HolidayGapCapture（不要動 L2）
  - 只在連假 4 天以上時介入
  - 進場：連假前 1 天日盤 12:00 確認空頭結構
  - 倉位：絕對小於 L2 的 1/3
  - 出場：開盤瞬間平倉（不等 SL）
  - 倉位上限：帳戶 5%
  - 必須有 OTM CALL 對沖
```

但這是**全新策略**，不該污染 L2 的成熟邏輯。

### 1.7 L2 取消假日限制的結論

**機構評估**：
- ✅ **保留 L2 HolidayFlat_v3**（已是正確設計）
- ❌ **不可取消假日限制**（違反機構標準 + 無統計支持）
- 🔄 **可選擇加強**（提前到日盤 flat）
- 💡 **如想做假日空** → 新策略，不污染 L2

## 二、S1 行為釐清（**回答用戶的誤解**）

### 用戶說
> 「S1 碰到節日就會強制在 05:00 之前完全沒倉位對吧？而平時還是會有跨日。」

### 正確答案：**S1 平時也不跨日**

#### S1 的時間機制 4 層

```powerlanguage
inputs:
    ExitTime(500),                  ← v2.4 每日強制 05:00 出場
    Holiday_Flat_Time(415),         ← 假日前夕提前 04:15 出場
    Settlement_Flat_Time(1230);     ← 結算日 12:30 出場

進場條件:
    if v_RangeReady and
       v_IsNightSession (Time >= 1500 OR Time < 500) and
       Time < ExitTime (= Time < 500) and    ← ★ 進場必須在 05:00 前
       Holiday_Block = false and
       Settlement_Day = false ...
       
出場 (Priority 0 + Daily Flat):
    Holiday: Time >= 415 → LX_NM_HolFlat
    Settlement: Time >= 1230 → LX_NM_Settlement
    Daily Flat: Time >= 500 AND Time < 1500 → 強制平倉
```

### S1 的真實運作時序

| 時段 | S1 行為 | 是否跨日 |
|------|--------|--------|
| 平日 15:00-23:59 夜盤前半 | **可進場** | — |
| 平日 00:00-04:59 夜盤後半 | 可進場（若無假日 block）| **不算跨日** |
| **平日 05:00** | **★ 每日 ExitTime 強制平倉** | — |
| 平日 05:00-08:44 | 無交易 | — |
| 平日 08:45-13:45 日盤 | **不進場**（v_IsNightSession=false）| — |
| 平日 13:45-15:00 | 無交易 | — |
| **假日前夕 04:15** | **★ HolidayFlat 提前平倉** | — |
| 結算日 12:30 | ★ Settlement 平倉 | — |

### 「跨日」的定義釐清

**S1 跨「日曆日」但不跨「交易日」**：
- 6/18 22:00 進場（calendar day = 6/18）
- 6/19 03:00 仍持倉（calendar day = 6/19）
- 6/19 05:00 強制平倉（calendar day = 6/19）

calendar 上跨了 6/18 → 6/19，但這**還是同一個夜盤 session**（6/18 15:00 ~ 6/19 05:00）= **同一個商品交易日**。

**S1 從未在「日盤之間」跨夜留倉**（不會有 6/18 持倉到 6/19 09:00 的情況）。

### S1 一句話總結

> **S1 每天 05:00 強制平倉，無論假日。假日只是讓平倉提前到 04:15**。
> S1 **從來不真正跨交易日**，是設計上的「夜盤日內」策略。

## 三、機構級開發評估框架（**未來所有新策略 / 優化必須走的流程**）

### 用戶指令
> 「必須要以機構的角度去思考開發以及優化的所有可能性。」

### 機構級評估框架（**10 維度檢核**）

#### 維度 1：Sharpe / Sortino / Calmar Ratio

任何優化提案必須計算這 3 個指標的**變化幅度**：

```
Sharpe = (年化報酬 - 無風險利率) / 年化波動
Sortino = (年化報酬 - 無風險利率) / 下行波動
Calmar = 年化報酬 / 最大回撤
```

**機構標準**：
- Sharpe > 1.5 才上架
- Calmar > 2.0 為佳
- 任何優化不能讓這些指標下降

#### 維度 2：Tail Risk 量化（VaR / CVaR）

```
99% VaR  : 99% 信賴區間下的單日最大可能損失
CVaR (ES): 超過 VaR 的平均損失（fat tail）
```

**機構標準**：
- 任何優化不能擴大 VaR > 10%
- CVaR < 帳戶 25% 才可接受

#### 維度 3：Correlation Matrix 跨策略

新策略 / 優化前必須：
- 計算與既有 6 隻策略的日 PnL 相關係數
- 任一相關 > 0.7 → 警示重複曝險
- 整體 portfolio Sharpe 必須優於單獨策略

#### 維度 4：Drawdown Clustering 分析

```
回撤是否集中在特定時段 / 市況？
連續 N 個月 DD 是否會擊破帳戶承受度？
```

**機構標準**：連續 12 個月回撤 < 30%。

#### 維度 5：Sample Size Statistical Significance

```
樣本 < 30 → 統計無意義
樣本 30-100 → 弱信心
樣本 100-500 → 中信心
樣本 > 500 → 強信心
```

**機構標準**：上 live 至少需要 100 筆樣本。

#### 維度 6：Walk-Forward / OOS Validation

```
WFE (Walk-Forward Efficiency) > 50%
OOS PF / IS PF ratio > 0.7
2022 熊市單獨 PF > 1.2
```

#### 維度 7：Regime Classification

```
策略在 bull / bear / range 三種市況各別表現？
是否依賴單一市況才賺錢？
```

**機構標準**：任一市況 PF > 1.0。

#### 維度 8：Cost Analysis

```
滑價 (Slippage)
手續費 (Commission)
期交稅 (Transaction tax)
機會成本 (Opportunity cost vs Buy-and-Hold)
```

**機構標準**：成本扣除後仍有正 alpha。

#### 維度 9：Operational Risk

```
MC 系統故障風險
Broker 連線中斷
人為操作錯誤
資料源失效
```

**機構建議**：
- 雙重平台部署
- 自動 reconciliation
- 操作 SOP 文件

#### 維度 10：Regulatory / Compliance

```
法規要求最大持倉
資金結算與清算
個人帳戶 vs 機構帳戶差異
```

### 未來開發 / 優化的強制 checklist

```markdown
[ ] 維度 1: Sharpe / Sortino / Calmar 預估變化已量化
[ ] 維度 2: VaR / CVaR 影響評估
[ ] 維度 3: 與既有策略相關性 < 0.7
[ ] 維度 4: Drawdown clustering 分析
[ ] 維度 5: 樣本數 ≥ 100
[ ] 維度 6: WFE > 50% + OOS 驗證
[ ] 維度 7: 三市況分別 PF > 1.0
[ ] 維度 8: 成本分析完整
[ ] 維度 9: Operational risk 評估
[ ] 維度 10: 法規 / 帳戶限制檢視
```

**不通過 → 不上 live**。
