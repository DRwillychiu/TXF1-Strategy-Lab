Tier 1 監控第一步：找資料來源，還沒寫程式。帳號、姓名、身分證一律遮罩。

## 結論
- 實盤機的下單大師在跑 **v4.0.0120**，程式從 `%USERPROFILE%\Downloads\_下單大師_\下單大師設定備份\系統_0930【v4.0.0120】\`（下稱 OM_DIR）執行；`C:\OrderMaster` 裡只有設定檔和 v4.0.0121 的壓縮包，不是執行中的版本。
- 實盤機的 MC 是 **KGI MultiCharts64**（`C:\KGI\KGI MultiCharts64\`），不是 MC9。舊文件寫 MC9 的地方要更正（另案）。
- 下單大師有三個可用來源，見下表。

## 欄位：B1（T log）
`[HH:MM:SS:mmm] T:[分公司-帳號][RequestID ]Future New ...`、`T:[RequestID] ACK`、`T:RCV 2002 [RequestID,券商委託序號][結果碼]`、`T:RCV 2010[序號]`、`T:RCV 2011[序號]`。
- 推論：2010＝委託回報、2011＝成交回報、2002 的 `[0]`＝送單成功。待以失敗單驗證。
- 同一檔混有其他兩個帳戶的回報，必須依帳號過濾。

## 11/20 案例重新判讀（推論，待 OMDB 證實）
| 時間 | 來源 | 事件 |
|---|---|---|
| 09:45:01.886 | OMLog | MC：L2 部位 0→−2，訊號價 36,578 |
| 09:45:01.944 | T log | 下單大師送出新倉單 |
| 09:45:01.975 | T log | 券商接受（2002 結果 0），委託序號 4566xxxx |
| 09:45:02.024 | T log | 成交回報（2011） |
| 畫面 | 截圖 | 委託 IOC 限價 36,389；成交 36,575 |

- 36,389 ≈ 訊號價 36,578 − 189：推論是下單大師把市價單轉成「保護價」IOC 限價送出，不是真的掛在 36,389。
- 實際滑價 ＝ 36,575 − 36,578 ＝ −3 點（賣低 3 點），在正常範圍。
- 「成交顯示 ROD」推論是回報欄位的顯示值，不是實際時效。待用 OMDB 原始欄位確認。
- 這筆的正確異常判定應該是「委託價和成交價差 186 點，原因是保護價」→ 第一版規則要用「成交價對 MC 訊號價」判斷，不用委託價。
- 11:17:14 L2 回補 −2→0，訊號價 36,376，同樣流程。

## 存法
- 原始檔照抄到 `data/order_monitor/raw/YYYYMMDD/`，不改；解析結果另存 `data/order_monitor/parsed/`。兩者都不進 git（含帳號、姓名）。
- 讀取時用唯讀方式複製一份再解析，不鎖下單大師正在寫的檔。
- 每筆存「取得時間 asof」。

## 只用當下看得到的資料
- 盤中檢查只用 asof 之前已落地的列；收盤後補進來的回報不回填盤中判定。
- 收盤對帳表可用全天資料，但每筆異常標「盤中首次發現時間」。

## v0.4 凱基 TradeCom 唯讀（Willy 11/20 選定）
依據：凱基官方《TradeCom 說明文件-期權》《TradeCom 回報格式附件-期權》（本機 Downloads\TradeComExample_20251206）。下單大師用的也是同一套（T log：TradeCom 1.4.8.8）。

| 需要 | TradeCom 來源 | 關鍵欄位 |
|---|---|---|
| 委託回報 | PT02010（`AutoSubReport`＋`AutoRecoverReport` 回補當天） | OrderFunc（新／改／刪）、**TimeInForce F/I/R**、**PriceMark（0＝限定範圍市價、1 市價、2 限價…）**、Price、OrderNo、PositionEffect（新倉／平倉）、BeforeQty／AfterQty、**ErrMsg**、**TaiDelCode（47／48＝交易所動態退單）**、Session、ReportTime |
| 成交回報 | PT02011 | **DealPrice**、DealQty、**CumQty／LeaveQty（部分成交）**、OrderNo、MarketNo、ReportTime |
| 送單結果 | PT02002 | ErrorCode（非 0 用 GetOrderErrMsg 查原因，含保證金不足） |
| 真實部位 | `RetrivePositionDetail`／`RetrivePositionSum` | 待確認：回傳欄位以實測為準 |

- 11/20 的 36,389 推論對應 **PriceMark 0＝限定範圍市價**：價格欄是保護價，不是限價。用 TradeCom 實測一次就能證實。
- 唯讀保證：程式只呼叫登入、回報訂閱與回補、Retrive* 查詢；**不呼叫任何下單、刪改單方法**，並寫測試掃描原始碼擋住。
- 憑證：沿用實盤機環境變數 `KGI_ID`／`KGI_PWD`（kgi_recorder 已用這組名字），不進 repo。
