**建立**：2026-08-06，源自 S16_S v1.11.0 → v1.15.0 的完整優化循環
**適用**：所有 `research` / `live_simulation` / `live` 策略的參數調整與機制增修
**定位**：`ENGINEERING_SYSTEM.md`（五支柱）之下的執行層 SOP。
promote 前的 5 件套驗證見 `non_WFA_validation_SOP_20260630.md`，兩者不重疊。

---

## 0. 核心心法：五個依序要問的問題

**不要一開始就掃參數找最佳值。** 那是第三個問題，不是第一個。

```
Q1  這個參數還在做事嗎？          -> 失效測試（§3）
Q2  它做的事是對的嗎？            -> 掃描找高原（§4）
Q3  這次改動只影響了該影響的嗎？   -> 逐筆位元比對（§5）
Q4  這是真的還是雜訊？            -> 配對檢定 + 選擇偏誤（§6）
Q5  未來的人會誤解它嗎？          -> 機制正名與註解（§7）
```

**Q1 最便宜、資訊量最大，卻最常被跳過。**
S16_S 這輪三次失效測試：兩次證實參數已死（其中一次讓 5 個 input 塌縮成 3 個），
一次證實仍在作用。每次只花 1 次回測。

## 1. 開工前：參數依據盤點（Provenance Audit）

### 1.1 為什麼要做

**參數依據會隨架構演進而失效。** 一個在架構 N 下掃出來的最佳值，
在架構 N+1 下**不是被推翻，是根本沒被驗證過**。

S16_S 實例：
- `Struct_Trigger_Pct = 1.20` —— 為了讓另一次掃描維持二維，**直接從隔壁那條腿複製**
- `Trail_Giveback_Pct = 80` —— 掃於「它是唯一保護」的時代，後來多了兩條腿
- `BE_Trigger_Pct = 0.80` —— 同上

三個都不是錯的，是**沒有依據的**。W5 十維評估會逐項問「為什麼是這個數字」，
「從隔壁抄的」不是能拿出去的答案。

### 1.2 依據等級

| 級 | 定義 | 處置 |
|---|---|---|
| **A** | 在**現行架構**下掃描驗證 | 可辯護，收案 |
| **B** | 有掃描，但在**舊架構**下 | **provenance 落差，須重驗** |
| **C** | 算術推導 / 平台常數 | 可辯護（但算術要驗算，見 §8 AP-7） |
| **D** | 從未掃描 | 列入待辦，或明確標記為設計判斷 |
| — | 純開關（True/False） | 不需依據 |

### 1.3 產出

一張表，欄位：`參數 / 現值 / 級別 / 依據 / 最後驗證於哪個版本`。

**B 級與 D 級就是這一輪的工作清單。**

## 2. 單一改動原則

> **每次只動一個參數。每次跑退化錨點。每次對預先登記的驗收標準。**

### 2.1 為什麼

樣本數決定了能負擔的維度。S16_S 有 129 筆交易、其中只有 21 筆會武裝停利腿。
**九維搜尋是曲線擬合，不是最佳化。**

### 2.2 例外：等價變換

若改動的目的是**證明兩組設定等價**（架構簡化），可以同時動多個參數，
但必須以**位元相同**為驗收標準，不是「差不多」。

S16_S 實例：`Trail 1.20/80 + Tier2 2.00/40` → `Trail 2.00/40 + Tier2 off`，
同時動三個參數，129 筆 × 13 欄位零差異，5 個 input 塌縮成 3 個。

## 3. 失效測試（Failure Test）— **本 SOP 最重要的工具**

### 3.1 定義

把參數推到**形同虛設**的值，跑一次回測，看結果是否與現況位元相同。

| 結果 | 意義 | 處置 |
|---|---|---|
| **位元相同** | 該參數從未決定過任何一筆出場 → **死參數** | 移除或塌縮；若是風險語意則保留但記錄 |
| **有差異** | 它確實在管某些交易 | 記錄它管的範圍與價值，才值得進一步掃描 |

### 3.2 怎麼選「形同虛設」的值 —— **這一步最容易做錯**

**必須讓該機制在它負責的整個範圍內都不可能生效，不是只是「放鬆」。**

S16_S 實例（`Trail_Giveback_Pct`，原值 80）：

| 候選 | 該帶最低點的鎖利 | vs 保本地板 10 點 | 判定 |
|---|---|---|---|
| 95 | 27 點 | **仍高於地板** | ❌ 只是放鬆，不是失效 |
| **99** | 5.4 點 | 低於地板 | ✅ 整帶失效 |

**做法**：算出該機制在其負責範圍**兩端**的輸出值，確認都低於會接手的下一層。
只驗一端會漏掉邊界。

### 3.3 判讀陷阱

**死參數不等於該刪除。** 要分清楚：

| 類型 | 例 | 死了怎麼辦 |
|---|---|---|
| **數值調校** | `Trail_Giveback_Pct` | 移除 / 塌縮 |
| **風險語意保證** | `BE_Trigger_Pct`（保證不倒賠） | **保留**。它的存在理由不是績效，是規則本身 |

## 4. 掃描設計

### 4.1 範圍：兩軸都必須有**內部極值**

| 情況 | 判定 |
|---|---|
| 最佳值落在區間**內部** | 範圍正確 |
| 最佳值貼在**邊界** | 範圍不足，往外延伸再掃 |
| **單調遞增/遞減、無極值** | **結構性訊號**，不是範圍問題 —— 該假設在此 regime 沒有 edge（S16_S v1.10.0 教訓） |

### 4.2 內建錨點

掃描網格裡**必須包含現行值**，且它必須跑出已知的績效數字。

**對不上就停，不要解讀** —— 代表有別的參數被動到。

S16_S 實例：11 格掃描含 `1.20`，跑出 `129T / 2,670,800 / PF 1.802717` 完全吻合，
掃描才可信。

### 4.3 收斂錨點（免費的第二錨點）

若掃描區間的一端會讓機制自然失效，那一端的收斂值**就是「該機制零貢獻」的基準**，
不必另外跑 `On=False`。

S16_S 實例：`Struct_Trigger_Pct >= 1.4` 全部收斂到 2,608,400，
那就是結構腿零貢獻的值。

### 4.4 檢查參數之間的隱性耦合

**掃描前先算一次：這個參數會不會被別的參數 clamp 掉？**

S16_S 實例：`Struct_Lookback` 的窗口是 `MinList(Lookback, 持倉根數+1)`，
而 `MaxHoldingBars = 24`。**所以 `Lookback >= 25` 在數學上全部等價** ——
掃 25/30/35/40 是掃四個相同的東西。

**耦合一旦發現，必須寫進註解**：任何變更被耦合的另一端，都要整組重驗。

## 5. 結果判讀

### 5.1 判讀順序 —— **不可先看淨利**

```
1. alpha 引擎是否被侵蝕（本策略的主要獲利出場結構）
2. Top-10 大贏家存活率
3. 最大單筆獲利是否下降
4. 最大回檔是否劣化
5. 觸發筆數（0 筆 = 太鬆；過多 = 在跟主機制搶交易）
6. 最後才看淨利
```

**理由**：S16_S 的 `0.30/35` 災難，過程是先砍掉贏家（Top-10 只活 1/10），
淨利才崩到 1,026,800。**先看淨利會看到「還好」的中間值，然後繼續往錯的方向調參。**

### 5.2 穩健性：取高原中心，不取最高分

**判準是鄰域平均** —— 真高原的鄰居也要高。

S16_S 實例：

| 候選 | 自身 | 左右鄰居平均 | 判定 |
|---|---|---|---|
| 0.60 | **2,844,800**（最高） | 2,517,800（**低於基準**） | 斷崖邊尖峰 ❌ |
| 1.00 | 2,761,600 | 2,698,600 | 高原中心 ✅ |

`0.60` 的左鄰只差一格就掉 535,600。**選最高分等於押注參數永不漂移。**

### 5.3 截斷訊號

即使淨利上升，這兩個指標劣化就要逐筆查：

- **平均贏家下降** —— 大贏家被砍小
- **贏家平均持有根數下降** —— 提早出場

S16_S 的 `0.60`：平均贏家 −14%、持有 20 根（vs 23）。這是它被否決的第二個理由。

## 6. 逐筆驗證

### 6.1 比對必須用「進場身分」配對，**不可用交易編號**

出場時點一改變，後續進場時機全部位移，交易總數也可能變。
用編號比對會拿 A 版第 91 筆去比 B 版的另一筆交易。

**配對鍵：`日期 + 時間 + 進場價`**

S16_S 實例：首次比對誤用編號，得出「Top-10 第一筆變成停損大虧」的錯誤結論；
改用進場配對後，該筆其實**完好無損**。

### 6.2 位元比對的欄位

不只比損益。至少比：
`交易編號 / 進場訊號 / 損益 / MFE / MAE / 出場訊號 / 出場價 / 出場日期 / 出場時間`

**「淨利相同」不等於「行為相同」** —— 可能是兩筆互相抵銷。

### 6.3 反推法：用出場價判斷是哪個機制生效

```
鎖利 = 進場價 − 出場價          （空單；多單反向）
回推峰值 = 鎖利 / (1 − giveback)
```

把每個候選機制的回推峰值算出來，**與該筆自己的 MFE 對照**：
回推值若超過該筆的 MFE，物理上不可能，該機制即被排除。

S16_S 實例：4 筆 Trail 出場，用基準 80 回推的峰值是 9.38% / 10.57% / 6.66% / 6.23%，
**全部超過各自的 MFE** → 基準 80 被排除，全部是分層 40 在管。

**這比「跑一次看結果」更強：它是物理反證，不依賴另一次回測。**

### 6.4 ⚠️ 報表 MFE ≠ 程式的峰值變數

| 量 | 基準 |
|---|---|
| 報表「最大可能獲利」 | **盤中**（High / Low） |
| 程式 `v_MaxProfit` 之類 | 通常是**收盤** |

**用 MFE 反推「峰值百分比」以判斷門檻是否觸發，一律會高估。**

S16_S 實例：某筆盤中 MFE = 1.24%，但收盤基準峰值必在 [1.00%, 1.20%)
—— 因為它在門檻 1.20 下沒觸發、1.00 下才觸發。

**判斷門檻是否觸發，用 §6.3 的出場價反推，不用 MFE。**

## 7. 統計檢定

### 7.1 配對資料要用配對檢定

兩個版本跑**同一批進場**，是 paired data。誤用非配對檢定會嚴重灌水標準誤。

```
正確：對逐筆差額取標準差，未改變的交易貢獻 0
      SE(sum) = sd(差額) × sqrt(N)
```

S16_S 實例：誤用非配對得 SE 1,386,494，正確配對得 995,352 —— 把真實效果誤判成雜訊。

### 7.2 選擇偏誤：掃了 N 格就要用 N 格的門檻

即使真實效果為零，**N 次抽樣的最大值本來就會顯著大於零**。
粗估：N 次獨立抽樣的期望最大值約 **2 個標準誤**（N 越大越高）。

**觀察到的最佳值若小於「純雜訊該產生的最大值」，等於什麼都沒挑到。**

### 7.3 誠實標註

`< 2 sigma` 一律標註**「統計上未確立」**，不可寫成「顯著提升」。

**但等價變換不需要檢定** —— 位元相同是證明，不是效果宣稱。

## 9. 寫回程式碼

### 9.1 必做

1. **參數預設值寫回 `.pla`** —— code = deploy = docs 三一致
2. **標頭記錄**：改了什麼、依據、掃描網格、被否決的候選與否決理由
3. **限制寫在檔案裡**，不只寫在文件裡（樣本數、sigma、未過的驗收項目）
4. **耦合警告寫在對應參數旁**（§4.4）

### 9.2 驗證改動範圍

**剝除註解後逐行比對，證明「只改了預設值，邏輯零改動」：**

```bash
# 概念：剝掉區塊註解後 diff，差異應只有 input 預設值
```

S16_S 實例：v1.14.0 與 v1.15.0 剝註解後**皆為 401 行**，差異只有 4 個預設值。

### 9.3 ⚠️ 預設值本身要跑一次

**手動設參數跑出來的結果，不等於預設值寫對了。**

**收案前最後一步：載入新版本，一個參數都不要動，直接跑，確認複現。**

S16_S 這一步抓不到錯（預設值寫對了），但它是唯一能抓到「小數點打錯」的檢查。

## 10. 機制正名（Q5）

**代數化簡程式碼，確認它做的事與名稱相符。**

S16_S 實例（A-1）：模組叫「結構停利」，設計文件寫「追蹤近期擺動高點」。
但化簡後：

```
空單獲利 = 進場價 − 收盤
∴ Highest(Close, N) = 窗口內獲利最少的那一根
∴ 鎖利 = （窗口內最小獲利） − 緩衝
```

加上窗口被持倉上限 clamp 到幾乎不滾動 ——
**實際機制是「進場後最低獲利追蹤」，不是結構追蹤。**

**行為有效，但名稱會誤導調參。** 有人可能為了「讓結構更靈敏」而調小回看根數，
實際上那會讓停損**更緊**（實測 5/10/15 都更差）。

**處置**：不改邏輯（已驗證有效），**改註解正名**，並寫上反直覺警告。

### 10.1 順帶檢查：程式順序 ≠ 成交順序

```
market 單 -> 下一根開盤成交
stop 單   -> 下一根盤中觸價成交
```

**開盤先於盤中。** 若同一根同時掛出兩者，**market 單先成交**，
即使 stop 單在程式中排在前面。

務必在註解中寫清楚實際的成交優先序，否則接手者會誤判。

## 12. 何時該停

**邊際報酬遞減是訊號，不是失敗。**

S16_S 出場端六個機制的增量：`+68,800 → +89,600 → +24,400 → +90,800`，
最後一項僅 1.37 sigma。

**停下來的判準**：
