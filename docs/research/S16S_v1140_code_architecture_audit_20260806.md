## 2. 發現

### A-1 ★ 架構性：「結構停利」實際上不是結構追蹤

**程式碼**
```powerlanguage
v_Struct_Window = MinList( Struct_Lookback, v_BarsSince + 1 );
v_Struct_Ref    = Highest( Close, v_Struct_Window );
v_Struct_Raw    = EntryPrice - ( v_Struct_Ref + Struct_Buffer_Pts );
```

**代數化簡**：空單的獲利 = `EntryPrice - Close`，故 `Highest(Close, N)` 就是
**窗口內獲利最少的那一根**。因此

```
v_Struct_Raw = （窗口內最小收盤獲利） - Buffer
```

**再加上窗口幾乎不滾動**：`MaxHoldingBars = 24` 而 `Struct_Lookback = 20`，
第一根要到第 20 根才輪出窗口，而交易最多活 24 根。

**實質行為 = 「進場以來最差收盤獲利 − 20 點」，不是「近期擺動高點 + 緩衝」。**

**佐證**（皆為實測，非推論）：

| 證據 | 內容 |
|---|---|
| Lookback 25/30/35/40 淨利完全相同 | 被 clamp 成同一個窗口 |
| Lookback 5/10/15（真正會滾動）反而更差 | 滾動行為並非效益來源 |
| `Struct_Trigger_Pct = 0` 淨利崩至 1,382,000 | 進場首根窗口只有 1 根，參考點是該根自己的收盤，鎖利立刻 = 當根獲利 − 20，形成極緊早期停損 |

**影響**：行為本身有效（+62,400 ~ +153,200），**但模組名稱、註解與設計文件描述的機制
（trail behind market structure / swing high / 只有破壞近期結構才出場）與實際計算不符。**

這會誤導未來調參 —— 例如有人可能為了「讓結構窗口更靈敏」而調小 Lookback，
實際上那會讓鎖利錨定在更近期、更高的獲利上，變成更緊的停損。

**處置**：不改程式碼（行為已驗證）。**改註解與文件，把機制正名為
「進場後最低獲利追蹤（Lowest-Profit-Since-Entry Trail）」**，並保留原設計意圖的說明與
為何實作偏離。

### A-4 三個門檻的比較基準不一致（風格，非缺陷）

```powerlanguage
BE     :  v_Profit    >= EntryPrice * BE_Trigger_Pct     / 100
Trail  :  v_MaxProfit >= EntryPrice * Trail_Trigger_Pct  / 100
Struct :  v_MaxProfit >= EntryPrice * Struct_Trigger_Pct / 100
```

BE 用**當根獲利**，另兩者用**峰值獲利**。

**邏輯上等價**：三者皆為 latch（設 True 後不再回復），而
`v_MaxProfit = max(v_Profit)`，故「`v_MaxProfit` 曾 ≥ X」⟺「`v_Profit` 曾 ≥ X」。

**非缺陷**，但閱讀時容易誤判 BE 的條件較嚴。建議統一為 `v_MaxProfit` 以消除歧義。

### A-5 ★ 出場優先序：「程式順序」≠「成交順序」

程式鏈中 P3（stop 單）排在 P4 GoldenCross / P5 TimeStop（market 單）**之前**，
但 P3 **不設 `ExitFired`**，所以同一根 K 棒可以同時掛出 stop 單與 market 單。

成交先後由**訂單型態**決定，不是程式順序：

| 型態 | 成交時點 |
|---|---|
| market 單 | 下一根**開盤** |
| stop 單 | 下一根**盤中觸價時** |

**開盤先於盤中，所以同根同時掛出時 market 單先成交 —— P5 蓋過 P3。**
這正是 25 筆 TimeStop 能存在的原因。

P3 真正「preempt」的情境是**跨根**的：stop 單在第 N 根掛出，於第 N+1 根盤中觸發，
早於第 N+1 根**收盤**才評估的 QS_Time。

現行註解（1254-1255）只寫了跨根情境，未寫同根情境。

**處置**：補註解。這是理解整條出場鏈的關鍵，不寫清楚下一個接手的人會誤判優先序。

### A-8 ★ 方法論：報表 MFE ≠ 程式 `v_MaxProfit`

| 量 | 定義 | 基準 |
|---|---|---|
| 報表「最大可能獲利」 | 整筆交易的最大有利偏移 | **盤中**（High/Low） |
| 程式 `v_MaxProfit` | `max(EntryPrice − Close)` | **收盤** |

**實例（2026-07-30，進場 40301）**
```
盤中 MFE       = 500 pt = 1.24%
收盤基準峰值    ∈ [403, 484] pt = [1.00%, 1.20%)
```
反推依據：該筆在 `Struct_Trigger = 1.20` 走保本 0、在 `1.00` 才走結構。
若收盤峰值真是 1.24%，兩個門檻下都會武裝，不會有差別。

**所有用 MFE 反推「峰值百分比」以判斷門檻是否觸發的分析都會高估。**

本 session 稽核前的 Trail 出場分層歸因即誤用 MFE，後以「出場價反推鎖利」
交叉驗證才確認結論不變（見 §3.2）。

**處置**：寫入方法論記憶。判斷門檻是否觸發，一律用
**出場價反推鎖利**（`鎖利 = 進場價 − 出場價`），不用 MFE。
