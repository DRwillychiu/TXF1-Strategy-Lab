# S16_S 進場來源實驗 — 空方 K 棒結構作為進場條件，已被否決

**日期** 2026-08-23
**建置** `Build_ID 260823`
**結論** 空方 K 棒結構**無法**取代或補充斜率閘門。n = 4,422，決定性否決。

---

## 0. 為什麼這份文件存在

這是這個專案第一次做出**有足夠檢定力**的實驗。

先前所有關於 K 棒的判斷都建立在 180 筆成交的損益上，而 180 筆的檢定力上界是
「每筆平均必須提升 134% 才可能被偵測到」。**在那個樣本上，任何進場濾網都無法被驗證。**

這次的樣本是 **3,212 筆（來源 B）＋ 1,210 筆（來源 C）**，而且是受控對照：
同樣的死叉母體，唯一差別在第二個條件是「斜率」還是「結構」。

## 2. 逐來源拆解 — 這是決定性的部分

| 進場標籤 | 筆數 | 合計 | 平均 | 勝率 | PF | 大魚 |
|---|---|---|---|---|---|---|
| `SE_MA_DeathCross`（A 死叉 + 斜率） | **165** | **+2,112,800** | +12,804 | **29.1%** | **1.89** | **7** |
| `SE_MA_StructLead`（B 死叉 + 結構） | **3,212** | **−11,826,800** | −3,682 | 14.9% | **0.52** | 3 |
| `SE_MA_StructLate`（C 結構 + 死叉在窗內） | **1,210** | **−5,642,800** | −4,663 | 14.1% | **0.48** | 1 |

**`SE_MA_DeathCross` 在三個模式裡完全相同（165 筆 / 2,112,800 / PF 1.89），一分不差。**
代表兩件事：R1 多頭否決規則在來源 A 上成本為 0；來源 B、C 是純粹的加法，
沒有污染來源 A。**這是一次乾淨的受控實驗。**

### 2.1 同一批死叉，兩個不同的第二條件

```
A  死叉 + 斜率      ->  PF 1.89
B  死叉 + 空方結構   ->  PF 0.52
```

**斜率有用，結構沒有。差 3.6 倍。**

### 2.2 結構連尾巴都抓不到

```
來源 A    7 隻大魚 / 165 筆    =  4.24%
來源 B    3 隻大魚 / 3,212 筆  =  0.09%     ← 差 45 倍
```

這一點特別重要，因為這支策略靠尾巴賺錢（前 7 大贏家佔淨利 90% 以上）。
**若結構真的能辨識空方行情，它至少應該在大魚上有一點命中率。它沒有。**

## 3. 反過來，這證明了斜率閘門

```
7,704 個死叉  ->  斜率閘門只留下 187 個（拒絕率 97.6%）
那 187 個     ->  PF 1.89
把 42% 的死叉用「有結構」放行  ->  賠 11,826,800
```

**這支策略的優勢在「選擇性」本身，不在「認得出型態」。**

`MinSlope_Rate = 0.050` 雖然是樣本內調出來的，**但拿掉它要付 1,180 萬。
這是這支策略所有元件裡，證據最強的一個。**

## 4. 架構與測試（程式碼保留，預設關閉）

```
R1（常駐，無開關）  進場那根帶多頭結構 -> 不下單
來源 A   死叉 AND 斜率                              KB_Entry_Mode >= 0
來源 B   死叉 AND 空方結構仍在有效期內                KB_Entry_Mode >= 1
來源 C   結構當根完成 AND 死叉在其有效期內 AND 空頭狀態  KB_Entry_Mode >= 2
```

**結構有效期 = 它自己形成所花的根數**（2/3/4/5），零自由參數，2026-08-21 裁示。

`scripts/research/s16s_entrysrc_test.py` 從出貨的 .pla 解析後窮舉：

| 檢查 | 規模 | 結果 |
|---|---|---|
| A1 mode 0 只能產生來源 1 | 15,600 狀態 | 0 違反 |
| A2 有效期對應根數 2/3/4/5 | 15 個代碼 | 0 不符 |
| A3 多頭結構否決全部三個來源 | 23,400 狀態 | 0 放行 |
| A4 mode 1 ⊃ mode 0、mode 2 ⊃ mode 1 | 全部 | 0 違反 |

**A2 第一次執行拒絕，而錯的是測試不是 .pla** —— regex 在五根子句裡誤匹配，
把代碼 13 讀成有效期 2。錨定 `else if` 後通過。

## 5. 這次為什麼會走到這裡 — 製程紀錄

2026-08-17 我用 180 筆成交的損益，算出「帶型態平均 453 / 不帶 24,586」，
**據此把閘門方向整個反轉，做成「有空方結構就擋掉進場」。**

一個叫「**支持空單**」的結構，接到一個叫「**Block**」的開關上 ——
**這句話本身就與用戶的目標（更多空方進場機會、更好的品質）直接衝突，
不需要任何資料就讀得出來。**

用戶 2026-08-23 指出後，架構才改成「結構是進場來源」。而改對之後測出來的結果是：
**方向改對了，但假設本身是錯的。**

### 立為紀律

> **任何新開關，動手寫之前必須用一句話寫出「什麼情況會發生什麼」，
> 　並且把那句話直接對照用戶說過的目標。對不上就是設計錯了，不必等資料。**

> **每一步都要自問：這樣做有實質幫助，還是只是把東西做大做複雜？**

## 6. 永久封存的結論

**以下方向已在 n = 4,422 上被否決，不再重試：**

1. 空方 K 棒結構**取代**斜率閘門（來源 B，PF 0.52）
2. 空方 K 棒結構在死叉之後**確認**（來源 C，PF 0.48）
3. 空方 K 棒結構作為**擋人的濾網**（2026-08-17 至 08-22 的整套配置，
   置換檢定 p = 0.054，且是最寬鬆版本）

**仍未測**：空方結構作為**必要條件**疊在斜率之上（死叉 AND 斜率 AND 有結構），
預期 172 → 約 73 筆，破每月 2 筆下限。
⚠️ 來源 B 的 PF 0.52 表示「有結構」在死叉上幾乎不帶資訊；
**3,212 筆分不出來的東西，172 筆更分不出來。**
