## 2. ⭐ 我的設計錯誤

### 2.1 我在 L1 抓到過同一個錯，這次在同一支程式的另一個位置又犯

**L1 設計時我抓到的陷阱**（2026-08-22）：

> 突破帶是**觸發器**不是**結構**。`Close > 凍結突破線` 當狀態條件會讓機制**永不觸發**，
> 因為停損與解除條件在同一瞬間成立。必須改錨均線本身。

**這次我對 L4 的判斷**（2026-08-24，本檔前一份）：

> **L4 的幾何是乾淨的。** 空單的停損在上、進場價在下，觸發線與停損線相隔 d，不會重疊。
> **這跟 L1 完全相反……L4 不需要改。**

**那句話只檢查了「觸發條件 vs 停損」。我沒有檢查「解除條件 vs 停損」。**

### 2.2 錯在哪，用程式碼講

```powerlanguage
{ 凍結初始停損 }
v_Stop_Level = v_Frozen_LockedTop + (ATR_Stop_Mult * v_Frozen_ATR);
             = 箱頂 + 2 x ATR              <-- 永遠在箱頂「上方」

{ 我寫的 DISARM }
if (Close of Data2 > v_ReEntry_BoxTop) ... then 解除
                     ^^^^^^^^^^^^^^^^ 就是那個箱頂
```

> **被這個停損帶走，代表價格「必然」曾經穿到箱頂上方 2 個 ATR。**
> **而我的解除條件，測的就是價格有沒有穿到箱頂上方。**
>
> **解除條件被停損本身蘊含。這是 L1 那個陷阱的鏡像版本。**

而且 DISARM 我刻意排在 FIRE **之前**（fail-safe），
所以只要那根 60M 收盤落在箱頂上方，**旗標在被設立的同一根就被清掉，存活時間為零。**

### 2.3 這不是唯一嫌疑，但它排第一

| # | 假設 | 為什麼可疑 | 為什麼還不能定案 |
|---|---|---|---|
| **H1** | **DISARM 被停損蘊含**（上方） | 停損結構上永遠在箱頂之上 | 解除測的是 **60M 收盤**，15M 觸價不等於 60M 收在上方 |
| H2 | FIRE 的 `v_is_in_consolidation` 擋掉 | 那是我後來自己補上去的 | 未量測 |
| H3 | FIRE 的 `Close < v_Trigger_Price` 擋掉 | 觸發價每根重算，可能移動 | 未量測 |
| H4 | 總經濾網 `v_Trend_Dir` / `v_Macro_Block` 擋掉 | 價格上漲後 60M 可能翻多 | 未量測 |
| H5 | **ARM 根本沒跑過** | `ExitFired` 或 `v_Trail_Active` 的行為與我假設不同 | **這會是更嚴重的實作錯誤** |

**在量到之前，全部只是假設。不猜，做二分。**
