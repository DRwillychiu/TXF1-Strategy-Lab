## 1. 這一版只做一件事

**v18 = v17 + 一條並列的 `CS_ReEntry` 進場路徑 + 一行停損繼承。**

**一次進場的四個條件、Priority 0–3 出場鏈、四個風險開關——一個字都沒改。**

### 1.1 為什麼是並列而不是併入 `CS_Entry`

| # | 理由 |
|---|---|
| 1 | **錨點需要**：`ReEntry_On = 0` 時整段必須惰性，才能逐筆重現 v17 |
| 2 | **可量測**：出場標籤共用，但**進場標籤分開**，才量得到二次進場自己的勝率 |
| 3 | **性質不同**：一次進場是**事件**（假突破當下），二次進場是**狀態**（價格回到某價位） |

### 1.2 出場結構完全共用

L4 的出場鏈掛在 `if MarketPosition = -1 then begin`（L672）——
**它只問「現在是不是空單」，不問這個空單怎麼來的。**

| 機制 | 二次進場 |
|---|---|
| P0 Kill / Registry / Holiday / **Settlement** | ✅ 自動 |
| P1 `CS_BreakExit` | ✅ 自動，且**與 DISARM 條件同源** |
| P2 `CS_TimeExit` | ✅ 自動，**時鐘重新計**（用戶裁示 A） |
| P3 `CS_SP` / `CS_BE` / `CS_SL` | ✅ 自動 |
| 引擎 `SetStopLoss` guard | ✅ 不會誤傷（其距離永遠比繼承後的停損寬） |

**唯一需要動的是凍結初始停損的繼承 —— 見 §3。**

## 2. 狀態機（頂層，Phase 2b）

```
(1) ARM      ReEntry_On = 1
             and v_Prev_MP = -1 and MarketPosition = 0     <- 剛變空手
             and ExitFired = 0                              <- 是停損單帶走的
             and v_Trail_Active = false                     <- 不是移動停損
             and 鏈長未超過 ReEntry_Max_Chain
               -> 記住 進場價 / 原始箱體 / 原始停損

(2) DISARM   Close of Data2 離開「原始箱體」任一邊
               -> 解除清空                （在 FIRE 之前檢查，fail-safe）

(3) FIRE     已武裝 and 仍在盤整 and 箱體有效
             and Close <= 原進場價
             and Close <  v_Trigger_Price
             and 總經濾網 / Rule #11 三閘門 / v_Risk_OK 全部重查
               -> SellShort("CS_ReEntry")

(4) RESET    CS_Entry 成交 -> 新循環，清空鏈與武裝
```

### 2.1 ⭐ 三個實作上的判斷，逐條說明

#### (a) 怎麼分辨「是被停損帶走的」

`ExitFired = 1` 代表上一根在倉的 K 棒下了**市價出場單**（Kill / Registry / Holiday /
Settlement / BreakExit / TimeExit）。`ExitFired = 0` 代表當時只有**掛著的停損單**。

`ExitFired` 在 `if MarketPosition = -1` 區塊裡設定，所以**變空手那一根它保留著在倉最後一根的值**。

> **`ExitFired = 0` + `v_Trail_Active = false`** ＝ 恰好就是我量到的 **11 筆候選集**：
> `CS_SL` 輸家 10 筆 + 引擎 `Stop Loss` 1 筆，合計 **−518,000**。

#### (b) 為什麼狀態機必須放頂層

現行進場區塊包在 `if v_is_in_consolidation and v_Box_Top > v_Box_Btm then begin`（L576–647）裡。

**放進去的話：盤整一消失，整個區塊不執行，`v_ReEntry_Armed` 就卡在 True，**
**下次盤整回來時用舊價位開槍。**

**且必須跑在空手重設區塊之前**——那個區塊會清掉 `v_Trail_Active` 與 `v_Stop_Level`，
而 ARM 正好要讀它們。

#### (c) FIRE 為什麼要求 `v_is_in_consolidation`

**兩個理由，一個語意一個機械：**

- **語意**：那是「一次進場條件仍成立」的一部分
- **機械**：`v_Trigger_Price` 與 `v_Risk_OK` 都在 Phase 2 那個區塊裡算。
  不加這條，就可能在「該區塊沒跑的那一根」開槍，讀到**上一根留下的陳舊值**

> 這是我建完之後自己複查抓到的，**不是原始設計就有**。
> 與 v17 檢查 `v_Risk_OK` 陳舊讀取是同一族。

## 3. 停損繼承（唯一改到出場側的一行）

**問題**：平倉瞬間，空手重設區塊清掉 `v_SL_Locked` / `v_Frozen_ATR` / `v_Frozen_LockedTop`。
二次進場成交時，凍結區塊會**用當下 K 棒的 ATR 重新鎖一次**——
**如果當下 ATR 變大，新停損會比原來更寬，等於「同一個論述第二次冒更大的險」。**

```powerlanguage
{ 空單：停損在進場價上方，較低 = 較緊，故 MinList。 }
if v_IsReEntry = true and v_Frozen_SL_Orig > 0 then
    v_Stop_Level = MinList(v_Stop_Level, v_Frozen_SL_Orig);
```

**L1 v32 是多單用 `MaxList`。同一條規則，鏡像。**
