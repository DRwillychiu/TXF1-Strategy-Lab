三行的「平均獲利 × 勝筆 = 毛利」「平均虧損 × 敗筆 = 毛損」「毛利 + 毛損 = 淨利」全部自洽，
截圖讀數無誤。

### 對應關係是怎麼判定的 — 不靠讀欄位

**贏家平均持倉 23 / 23 / 14。** 一個會提前平倉的規則，**只可能縮短持倉，不可能拉長**。
所以持倉最短的那一格必定是觸發最多的 mode 2，關閉的那一格必定是 23 根。
再加上 mode 0 與 mode 1 的最大策略虧損完全相同（−505,600），mode 2 不同（−492,600），
對應關係唯一。這是物理，不是欄位辨識。

## 2. 決定性的一項 — mode 2 砍的正是尾巴

```
毛利   5,020,400 -> 4,330,400     -690,000
毛損  -2,526,000 -> -2,420,800    +105,200

付出 690,000 的獲利，換到 105,200 的少虧。6.6 比 1 的爛交換。
```

**贏家平均持倉 23 根 -> 14 根，平均獲利 −23.6%。**
勝筆反而從 54 增加到 61 —— 它把大贏家切成一堆小贏家。

回檔只改善 **2.6%**（−505,600 → −492,600），代價是淨利 **−23.4%**。

> 這正是 08-24 動手寫程式前就寫進設計文件的風險：
> 「前 7 大贏家佔淨利 90% 以上，`SX_MA_TimeStop_Pct` 10 筆 / 2,479,200，
> **mode 2 是唯一可能砍掉它的模式**。」**預測成立。**

## 3. mode 1 為什麼也沒用 — 而且方向和直覺相反

只在虧損時平倉，理論上應該減少毛損。**實際毛損反而增加 26,000。**

```
勝筆 54 -> 52     兩筆「當下在虧、但後來會轉贏」的單被砍掉
平均虧損 −20,705 -> −20,581   個別虧損確實有變小，但幅度遠不足以抵銷
```

淨利 −63,200，**最大策略虧損一分不變（−505,600）**。付出成本，零風險改善。

---

## 4. 一個沒被測到的版本 — 不可過度宣稱

**這次測的是「現行 9 種 3 根以上多頭結構」，而其中 97% 的觸發只來自
三內部上漲（12,458 次）與三外部上漲（12,074 次）。**
用戶原話舉的例子「連三紅」= 三白兵，只佔 **620 次 / 2.4%**。

也就是說，**被否決的是「用寬鬆的 3 根多頭結構當出場」，
不是「用三白兵當出場」** —— 後者根本沒被測到。

### 但它也測不了

```
三白兵 620 次 / 421,513 根 = 0.147%
平均持倉 12.3 根 -> 一筆交易期間至少遇到一次 = 1.79%
176 筆 x 1.79% = 約 3 筆
```

**3 筆無法產生任何可信的結論**，這回到 2026-08-22 算出的同一個檢定力天花板。
要做只能當作「規則性保護」直接裁示採用，不能宣稱它被驗證過。

## 5. ⚠️ 錨點沒有重現 — 必須記錄

| | 錨點（`Build_ID 260823`，資料至 08-22） | 本次 mode 0（`260825`） |

| 筆數 | **172** | **176** |
| 淨利 | 2,265,200 | 2,494,400 |

**最大策略虧損一分不差**，代表權益曲線在回檔之前完全相同 —— 差異在尾端多出的 4 筆。

`260825` 相對 `260823` 的程式碼改動只有：新增代碼 31/32/33 進 R1（常駐否決）
與 `v_ReEntry_Filt_OK`。**這兩處都只能讓交易變少，不可能變多。**
因此 **4 筆的增加只能來自資料，不可能來自程式碼。**

⚠️ **需向用戶確認回測資料的結束日期。**（記憶規則：設定表的「結束日期」是要求範圍，不是實際資料範圍。）

**三格之間的比較不受影響** —— 同一批次、同一份資料、只有一個 input 不同，是乾淨的受控對照。
