## 1. 為什麼是一次掃描，不是「三次驗證 + 兩段掃描」

原本規劃是 3 個驗證格 + 22 個主掃描格，分開跑。**改掉。**

`MaxHold_Pct` 是數值 input，MC12 最佳化器看得到（布林才看不到）。
所以整段用**同一個等差**掃完即可，驗證格自動落在格點上：

```
MaxHold_Pct   1.00  ->  5.00   step 0.05   =  81 格
```

**一次跑完。省下三次獨立回測，而且把驗證點從 3 個變成 27 個。**

### 1.1 其他 input 一格都不准動

| Input | 必須維持 | 理由 |

## 3. P5 —— 這次掃描最有價值的一個數字（免費取得）

全庫 176 筆的 MFE 最大值是 **2.29%**，而這個上限是 limit 單自己造成的。
所以 **2.30 以上，報告裡沒有任何一筆交易能告訴我們價格還會不會走。**

但掃描會直接給答案，而且是免費的：

**當 `MaxHold_Pct` 高到再也沒有任何一筆觸及時，趴數目標等於不存在。**
高段那些格子會收斂成同一個常數 —— 稱它 **N∞ = 沒有趴數目標的策略值多少錢。**

| 若 | 則 |
|---|---|
| **N∞ > 2,474,800** | **`MaxHold_Pct = 2.30` 正在毀掉錢。**目標本身是負貢獻 |
| **N∞ < 2,474,800** | 目標有存在價值，最佳點落在 2.30 與收斂點之間 |
| **N∞ = 2,474,800** | 現行值已在收斂平台上，往上沒有空間 |

**這是整輪最決定性的一格，而且不必額外跑任何東西。**
