## 2. 為什麼「至少 3 根」不是又一個被調出來的參數

這是本週最需要說清楚的一點，因為前五天正是死在「拿 180 筆損益去挑配置」。

**3 根是結構的定義，不是掃出來的門檻。**
一個要花 3 根以上才蓋出來的反轉，本身就比 2 根的更有份量；
而且進場側早就用同一條規則 —— **結構有效期 = 自己形成的根數** —— 零自由參數，2026-08-21 裁示。

它同時把觸發面積縮小三倍，這是從既有普查（421,513 根）直接算出來的，不是估的：

| | 型態 | 出現次數 | 佔全部 K 棒 |
|---|---|---|---|
| 2 根多頭 | A02 / A06 / A08 / A19 / A21 | 77,637 | **18.4%** |
| **3 根以上多頭** | B26 / B28 / B30 / B37 / B38 / C42 / C43 / C46 | **25,433** | **6.0%** |

平均持倉 12.3 根。若用 2 根版本，**約九成的交易都會被打斷** —— 那不是保護，那是換一支策略。

## 3. ★ 實作上發現的真缺陷：串接會吃掉 3 根型態

原本打算直接讀 `v_KB_Code`。**這樣寫會靜默漏掉。**

型態辨識是 first-match-wins 串接，而 **B28 三內部上漲的定義本身就包含一個多頭孕線**
（A06，代碼 17，排在前面先檢查）。單元測試在自己的 fixture 上就抓到兩個：

```
MASK 26 C42 rising three methods      reported as 16 <-- A02 bullish engulfing
MASK 28 C46 bullish three-line strike reported as 16 <-- A02 bullish engulfing
```

**若用代碼範圍判斷，C42 與 C46 永遠讀不到。**

修法：八個 3 根以上的多頭條件改成**無條件先舉旗** `v_KB_Bull3`，之後才去爭代碼。

```powerlanguage
if <條件> then begin
    v_KB_Bull3 = True;
    if v_KB_Code = 0 then v_KB_Code = 21;
end;
```

出場讀的是**旗標**，不是代碼範圍。T6 把這件事變成可執行斷言（見第 6 節）。

放在 P1 QuickStop 之後、P2 ML 之前：既有的快速風控仍先走，也不會被獲利保護腿搶先。

### 製程事故（留紀錄）

第一版改寫腳本用 `.*?` 加 `re.S` 去比對區塊。
非貪婪仍從**最早**的起點開始，於是代碼 21 那一次比對從**代碼 1** 一路吃到代碼 21，
**把 20 個區塊換成 1 個**。

**`verify_pla_semantics.py` 依然回報 PASS 23** —— 結果是合法的程式碼，只是行為不同。
是「代碼必須完整 1..30」這個獨立檢查抓到的。

> **改寫程式碼的 regex 一律用 `[^;]`，不用 `.*?`。**
> **語意驗證器擋不住這種傷害，只有「不變量還在不在」的檢查擋得住。**
