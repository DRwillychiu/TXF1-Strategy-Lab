## 2.5 ★ 斜率公式改寫（v1.19.0 – v1.20.0）—— 可比性的斷點

### 改了什麼

```
v1.18.0 以前   v_Slope = v_ZLEMA_Fast[1] - v_ZLEMA_Fast          點數
v1.20.0 起     v_Slope_Rate = ( Close[1] - Close ) / Close * 100
                              / 實際經過分鐘                      百分比／分鐘
```

| 版本 | 日期 | 主題 | 錨點 | 說明 |
|---|---|---|---|---|
| v1.19.0 | 08-11 | 六種公式對照台 | 118 ／ 3,098,400 | 量綱路線 **REJECTED** |
| v1.19.1 | 08-11 | dy/dx 形式化 | 118 ／ 3,098,400 | 位元相同 |
| v1.19.2 | 08-11 | 公式重述 | 118 ／ 3,098,400 | 位元相同 |
| **v1.20.0** | 08-12 | **速率式（`Slope_Form`）** | 118 ／ 3,098,400（預設仍為 Form 1） | Form 2 實測 **128 ／ 748,000 ／ PF 1.3825** |

### 四個項要分開記帳

| 項 | 目的 | 實測 |
|---|---|---|
| **÷ 實際經過時間** | 排除跳空汙染 | ✅ 時段第一根進場：Form 1 有 **8 筆（−54,800）**，Form 2 **0 筆** |
| **÷ Close** | 讓門檻跨指數位階一致 | ✅ 年度分布成立（見 §0） |
| **÷ Close（第二個作用）** | **拆掉一個被擬合出來的固定常數** | ✅ **見下，這是換公式最根本的理由** |
| **分子 `Close[1]−Close`** | 抓市場的下跌量 | ❌ **−2,350,400** |

### ★ 為什麼「換掉固定點數」本身就是價值 —— 與績效無關

`MinSlope = 28` 這個值的來歷是 **v0.5 的 GA，在 1024 組合裡挑出來的**。
它是一個**被擬合出來的常數，而且單位是點數**。

點數門檻有一個結構性問題：**它的實際嚴格度會隨指數位階自己漂移。**

```
28 點 ÷ 2019 指數 ~10,000  =  0.28%
28 點 ÷ 2026 指數 ~45,000  =  0.062%          早年緊 4.5 倍
```

意思是：

| | 點數式 `MinSlope = 28` | 百分比式 `MinSlope_Rate = 0.050` |
|---|---|---|
| 擬合基礎 | 某一段指數位階下的 GA 最佳解 | 與位階無關的比例 |
| 指數翻倍後 | **門檻自動鬆一半，策略行為改變而無人察覺** | **不變** |
| 維持有效性的代價 | **必須定期重新擬合** | 不需要 |
| 過擬合曝險 | 每次重擬合都再消耗一次樣本內自由度 | 一次定義，長期有效 |

> **一個必須定期重新擬合才能維持的常數，本身就是一個持續產生過擬合的來源。**
> 換成比例式之後，這個常數不再需要被重新擬合 —— **未來的過擬合風險被拆掉了，
> 而這件事完全不會出現在任何績效欄位上。**

年度分布的改善（§0）是這個性質的**症狀**，不是原因。真正的原因是量綱錯了：
用點數去衡量一個會漂移的價格序列，門檻的意義就會跟著漂。

### 交易筆數上升也是實質收穫

`118 → 180`（+52.5%）。這不只是「多做交易」：

- Rule #13 的「樣本數 ≥ 100」從**勉強過**變成**確實過**
- 年度分布從 3 個零交易年變成 0 個（§0）
- **W4 九視窗、三市況 PF、Sniper Bear PF 從「算不出來」變成「算得出來」**

**統計檢定力的提升，本身就是 PROMOTE 的前置條件。**

進場配對比對（`(日期, 時間, 進場價)` 配對）：

| | 筆 | 損益 |
|---|---|---|
| 兩式都進 | **28** | +1,050,000（兩邊完全相同） |
| 只有 Form 1 進 | 90 | **+2,048,400**（含前五大贏家全部） |

**機制**：ZLEMA(25) 每根只吸收約 2/26 的移動，`Fast[1]−Fast > 28` 要求**持續累積的跌勢**
＝趨勢確認；`(Close[1]−Close)/Close/分鐘` 抓的是**單根暴跌** ＝ 追在衰竭點。

> **採用 Form 2 是「公式正確性」的裁示，不是績效裁示。**
> 起點是 748,000 不是 3,098,400，這一點不可被事後重新詮釋成「最佳化的成果」。

## 7.3 ★ 進場端兩項未完成（2026-08-15 用戶指出）

參數 campaign 結案不等於進場邏輯完成。以下兩項是**新機制開發**，不是參數最佳化。

### 7.3.1 開盤跳空只處理了一種形態

現行 `Gap_Filter_On` 擋的條件是**單一組合**：

```
時段向下跳空  且  第一根收在自己的開盤價之上
＝ 「跳空開低 → 當根 V 轉」
```

**沒有處理的形態：**

| # | 形態 | 現況 |
|---|---|---|
| 1 | **向上跳空**（任何後續走法） | 完全未處理 |
| 2 | 向下跳空 ＋ 第一根續跌 | 不擋（可能是對的，但**從未驗證**） |
| 3 | 向下跳空 ＋ 第一根十字／長上影／長下影 | 未分類處理，全部併入「收在開盤之上／之下」二分 |
| 4 | 跳空幅度分級 | 只有單一 `Gap_Down_Min_Pct` 門檻，無大／中／小跳空的差別處理 |
| 5 | 第 2、3 根的獨立規則 | `Gap_Scope_Bars = 3` 只是把**同一條規則**的作用範圍延長，不是針對第 2/3 根寫的規則 |

> ⚠️ **與 §2.5 的敘述要分清楚，否則會自相矛盾。**
> 該節說「跳空是被公式解掉的、濾網只剩殘渣」—— 那句話的範圍是
> **跳空造成的斜率汙染**（時段第一根的 `[1]` 指向上一時段）。
> 這裡講的是**進場品質篩選**，是不同的目標：
> 汙染已解，但「各種跳空形態下該不該進場」**從來沒有被完整測過**。

### 7.3.2 K 棒型態尚未接進進場結構

`v_KB_Type` 的 18 型分類邏輯在 v1.16.0 就寫好了，四個參數也宣告了：

```
KB_Body_Long ( 0.75 )   KB_Body_Mid ( 0.30 )
KB_Body_Small ( 0.05 )  KB_Shadow_Ratio ( 2.00 )
```

**但 `v_KB_Type` 寫 18 次、讀 0 次 —— 完全未接線。** 掃這四個參數不會有任何變化。

**目標**：把 K 棒型態接進進場條件，作為**多組合判斷**的一個維度。

> ⚠️ **接線時必須避開循環論證。**
> 用一根 K 棒自己的 OHLC 算出來的統計量，**被該棒的分類定義所決定** ——
> 「長黑 K 的開→收為負」是恆真，不是實證。
> **可用的非循環證據只有兩種**：型態的發生頻率、以及
> **第一根型態 → 第 2~N 根走勢**。詳見 `feedback_backtest_comparison_method`。

### 7.3.3 這兩項與驗證階段的順序

兩者都是**新增進場條件**，會改變交易母體 —— 一旦動了，
**B4–B14 的所有出場參數又會落在舊母體上**（就是 v1.20.0 之後發生過的事）。

| 選項 | 後果 |
|---|---|
| **先驗證（W4 / Rule #13 / #18）再開發** | 驗證的是現在這個確定的組態；通過後再開發，屆時只需重跑受影響的批次 |
| 先開發再驗證 | 母體再變一次，出場參數要再重掃一輪，而且驗證會被延後更久 |

**建議先驗證。** 但這是排程判斷，不是技術限制。

### 7.4.2 C 的量測：累積不如快照

### 7.4.3 ★ 控制組：這是開盤特有現象，不可外推到每根 K 棒

同一套量測套在 **11,470 個隨機盤中錨點**上：27 格只有 2 格 p<0.05（期望 1.35）。

| | 時段開盤 | 盤中隨機 |
|---|---|---|
| **符號** | **負**（下影 → 後續上漲） | **正**（相反） |
| **隨 horizon** | **增強** p 0.05→0.01→0.00 | **消失** p 0.03→0.36→0.62 |

**符號相反、持續性相反 —— 不是同一效應變弱，是不同的東西。**
母體維持 **3,669**，不是 418,096。

### 7.4.6 一個仍未解的顛倒

`Gap_Rise_Min_Pct = 0.20` 從 v1.16.0 起就是**開著**的，依據是 **n = 1**，
而它在 3,669 個開盤上**複製不出來**（p = 0.24 ~ 0.95）。

本次把有證據的那條打開，修掉了顛倒的一半。**退役另一半需要它自己的事前註冊檢定**，
不能靠重讀那張已經判它不顯著的掃描表 —— 那會變成用同一份資料做兩次決定。
