## 2. 驗證方法（不依賴推算）

### 2.1 決定性證據：repo 內部先例

`L2_TrendShort` 同為 60M 策略，其 input 註解明文記載 60M 夜盤網格的實際 K 棒時戳：

```
Holiday_Flat_Time ( 300 ),   { 03:00 trigger on 60M grid -> fill 03:00, retry 04:00 }
```

→ 60M 夜盤 K 棒收在 **03:00 / 04:00**，不是 04:15 / 04:45。

`L1_TrendLong` 為 45M，用 345，註解記載「03:45 trigger -> fill 03:45, retry 04:30」
→ 45M 網格從 15:00 起算：…03:00, 03:45, 04:30。吻合。

**兩支不同時框的策略各自依網格調整過門檻，且註解記載的時戳互相一致。**
這證明夜盤 K 棒自 15:00 session 開盤起算對齊。

### 2.2 佐證：MC12 實際回測資料

S16_S v1.12.0 交易明細（5M）的所有成交時戳皆為 `HH:MM`，MM ∈ {00,05,…,55}，
夜盤尾段觀察到 03:00 / 03:25 / 03:45 / 04:35 / 04:45。
→ 5M 網格對齊整點，與 15:00 起算一致。

### 2.3 60M 夜盤 K 棒推導

夜盤 15:00–05:00 = 14 小時，60M 恰好 14 根，收盤時戳：
```
16:00 17:00 18:00 19:00 20:00 21:00 22:00 23:00 00:00 01:00 02:00 03:00 04:00 05:00
```
S3_L 原窗口 `Time >= 415 and Time <= 455` → **區間內零根 K 棒**。

### 2.4 結構性論證（與對齊方式無關）

窗口 [0415, 0455] 寬 40 分鐘，**小於 60 分鐘的 K 棒間隔**。
即使對齊方式不同、僥倖命中，也只會命中至多一根，且任何 session 時間調整都會靜默失效。

> **鐵則：假日窗口寬度必須 >= Data1 的 K 棒間隔，且必須排除 session 最後一根。**

排除最後一根（60M 為 05:00）的理由：該根的 `next bar at Market` 會成交在
**下一個 session 開盤（08:45）**，即休市之後，等於沒有保護。
