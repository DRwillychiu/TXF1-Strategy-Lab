## 1. 公式定案

### 1.1 使用者的原始陳述

```
斜率 = ( 瞬時點數 / 大盤點數 ) / 時間
```

五點裁示（2026-08-11）：

| # | 裁示 | 實作 |
|---|---|---|
| 1 | 時間是**變化量的時間**，A時間 − B時間 | `TimeToMinutes(Time) - TimeToMinutes(Time[1])` |
| 2 | **不保留**除以時間（無跨週期需求） | 式子裡沒有 `/ 時間` |
| 3 | 斜率就是**前後 5 分鐘**的斜率 | 時間差當**合法性閘門** |
| 4 | 改成正確公式並**標清定義** | 分母改起始值；註解寫明非「瞬時」 |
| 5 | **維持 ZLEMA** 當分母 | 未改 |

### 1.2 三點合成的結果

第 1、2、3 點合起來，**邊界排除從「一條額外規則」變成「定義的必然結果」**：

```powerlanguage
if CurrentBar > 1 then begin
    v_Elapsed_Min = TimeToMinutes( Time ) - TimeToMinutes( Time[1] );
    if v_Elapsed_Min <= 0 then v_Elapsed_Min = v_Elapsed_Min + 1440;
end else v_Elapsed_Min = 0;

if BarInterval > 0 then
    v_Slope_Adjacent = ( v_Elapsed_Min = BarInterval )
else
    v_Slope_Adjacent = False;

if v_ZLEMA_Fast[1] <> 0 then
    v_Slope_Pct = ( v_ZLEMA_Fast[1] - v_ZLEMA_Fast ) / v_ZLEMA_Fast[1] * 100
else
    v_Slope_Pct = 0;
```

**時間放在閘門裡，不放在值裡。** 過閘門的每一根 dx 都恰好是 `BarInterval`，
除以常數等於把門檻乘以常數，零資訊。

### 1.3 dy 與 dx 量的是同兩個瞬間

```
   Time[1] / v_ZLEMA_Fast[1]              Time / v_ZLEMA_Fast
   = 前一根收盤那一刻                       = 當根收盤那一刻
            |                                     |
   ─────────●─────────────────────────────────────●─────────
            |<─────────────── dx ────────────────>|
            |<─────────────── dy ────────────────>|
```

**分子與分母跨完全相同的區間 —— 這才是合法的變化率。**

| 情況 | dx | 其中無交易 |
|---|---|---|
| 時段內 | **5 分** | 0 |
| 0500 → 0850（日盤開） | **230 分** | **225 分** |
| 1345 → 1505（夜盤開） | **80 分** | **75 分** |

**除以 230 等於主張市場在那 225 分鐘裡逐步下跌。它沒有 —— 那段一筆交易都沒有。
斜率在那裡是「未定義」，不是「被壓縮」。**

## 2. 正確性驗證：418,096 根逐根複製

以 1 分 K（2019-01-02 ~ 2026-08-01，2,070,714 根）連續分鐘聚合成 5 分 K，
**逐根複製 PowerLanguage 的 `TimeToMinutes` 與 +1440 補正**，與真實經過分鐘對照：

| 檢查 | 次數 |
|---|---|
| 程式判定相鄰、**實際不相鄰**（汙染放行） | **0** |
| 程式判定不相鄰、**實際相鄰**（誤擋好資料） | **0** |

**`v_Elapsed_Min = 5` 的比例 99.10%（414,346 根），其餘 3,750 根正確排除。**

### 被排除的分類

| 前一根 → 當根 | 程式算出 | 真實經過 | 次數 | 類型 |
|---|---|---|---|---|
| 1345 → 1505 | 80 | 80 | 1,742 | 日盤收 → 夜盤開 |
| 0500 → 0850 | 230 | 230 | 1,432 | 夜盤收 → 日盤開 |
| 0500 → 0850 | 230 | **3,110** | **333** | **跨週末** |
| 1330 → 1505 | 95 | 95 | **91** | **提前收盤日** |
| 0500 → 0850 | 230 | 4,550~16,070 | **65** | **跨連假** |
| 2330~2350 → 0000 | 10~30 | 10~30 | **22** | **盤中缺口／臨時休市** |

**後四類（511 次）是序數判定（`v_Bars_In_Sess = 1`）完全抓不到的。**

### 跨午夜

原始資料只有 `00:00`、無 `24:00`。

```
2355 → 0000     0 − 1435 = −1435  → +1440 = 5   ✅
0000 → 0005     5 − 0    = 5                     ✅
```

**`if v_Elapsed_Min <= 0 then +1440` 必要且充分。**

## 5. 為什麼封閉 —— 成本單位

**滑價成本是固定點數，不隨指數縮放。**

| 年 | 中位 5 分 K 幅度 | 10 點成本佔該幅度 | 成本負擔（對 2026） |
|---|---|---|---|
| **2019** | **4.0 點** | **250.00%** | **12.25×** |
| 2020 | 8.0 | 125.00% | 6.12× |
| 2021 | 10.0 | 100.00% | 4.90× |
| 2022 | 12.0 | 83.33% | 4.08× |
| 2023 | 8.0 | 125.00% | 6.12× |
| 2024 | 16.0 | 62.50% | 3.06× |
| 2025 | 17.0 | 58.82% | 2.88× |
| **2026** | **49.0 點** | **20.41%** | **1.00×** |

**2019 年一根 5 分 K 的典型幅度連來回成本都跨不過。**

### 門檻的成本覆蓋

| 形式 | 2019 | 2026 |
|---|---|---|
| **固定 28 點** | **2.80×** | **2.80×** |
| 百分比 0.05 | 0.54× | 1.91× |
| 百分比 0.1166 | 1.25× | 4.45× |
| 百分比 0.2615 | 2.80× | 9.97× |

> **點數門檻與它真正在防的約束同單位，成本覆蓋八年恆定。
> 百分比對「指數」尺度中性，對「成本」尺度錯誤。**

要讓 2019 追平 2.80×，需 `MinSlope_Pct = 0.2615` —— 但那在 2026 是 **99.7 點**門檻，
而 **2026 佔 88% 的淨利**。

## 7. 兩項新發現的缺陷（均未修）

### 缺陷 A ── 跳空造出的死叉仍會解除二次進場武裝

```
行 2402   if v_Death_Cross = True then  v_ReEntry_Armed = False     ← 假交叉在這裡毀掉狀態
行 2598   v_FirstBar_Block 計算                                      ← 保護在這裡才出現
```

`v_Death_Cross` 同樣使用 `[1]`，在時段第一根同樣是跳空造出來的。
`v_FirstBar_Block` 擋掉了**進場**，但擋不掉那個假交叉對**狀態機**的副作用。

> **排除「進場」與排除「量測」是兩件事，v1.19.2 只做了前者。**

**處置**：需單獨開版（會改行為，不可與格 2 同版否則歸因混淆）。

### 缺陷 B ── 凍結 ATR 的跳空汙染

`ATR_Len = 14`，時段開盤後前 14 根的 ATR 仍含跳空的 True Range。
`v_Frozen_ATR` 在進場當根鎖定，**跟著整筆交易到底**。

| | 筆數 | 占比 | 損益 | 每筆 | 勝率 |
|---|---|---|---|---|---|
| **開盤後 1-14 根進場** | **36** | **30.5%** | 960,000 | 26,667 | **36.1%** |
| 第 15 根以後 | 82 | 69.5% | 2,138,400 | 26,078 | 26.8% |

**30.5% 的交易帶著被灌大的停損距離 —— 但它們的勝率反而更高。方向未知，需單獨實驗。**

`Slope_Require_Adjacent` 修不到這個，它只擋第 1 根。

## 8. 已修：`BarInterval` 護欄回歸

v1.19.1 有 `BarInterval > 0`（因為它要除）；v1.19.2 拿掉除法時把護欄一起弄丟了，**那是迴歸**。

若 `BarInterval` 不回報分鐘，比較永遠不成立 → 開關打開時所有進場被擋。
**方向安全（fail-closed）但靜默**，且同檔已為 `Tail_Signal_Lead_Bars` 寫了同類警告，前後不一致。

**已補回，零行為改動。**
