## 1. ✅ 已修正缺陷 A — 12 種兩根型態缺時段閘門

### 1.1 缺陷

`v1.26.0` 中，三根以上型態有 `v_Bars_In_Sess >= 3 / 4 / 5` 閘門，
**但 12 種兩根型態完全沒有 `>= 2` 閘門**：

| 家族 | 代碼 | 型態 |
|---|---|---|
| 支持空單 | 1–5 | 空頭吞噬、空頭孕線、空頭十字孕線、鑷子頂、高價配 |
| 反對空單 | 14–18 | 多頭吞噬、多頭孕線、多頭十字孕線、鑷子底、低價配 |
| 中性 | 27–28 | 內含線、外包線 |

後果：在時段第一根，`bar[1]` 是**前一個時段的最後一根**，
中間隔 **75 分鐘**（日盤→夜盤）或 **3 小時 45 分**（夜盤→日盤）。

**「隔著 3 小時 45 分的吞噬」在定義上不成立。**

### 1.2 用戶從原理推出這個缺陷

> 「今天實際上的吞噬就不應該出現在收盤當根發生，
> 　因為吞噬型態只能夠發生在有連續 K 棒出現的時間區段中。」

**這是先有邏輯推導、後有程式碼驗證，不是從數據挖出來的。**

### 1.3 實測曝險（全 418,096 根 5 分 K）

時段第一根共 **3,669** 根。

| 型態 | 總觸發 | 跨時段誤觸發 | 佔比 |
|---|---|---|---|
| A01 空頭吞噬 | 27,144 | **104** | 0.38% |
| A05 空頭孕線 | 28,736 | 47 | 0.16% |
| A07 空頭十字孕線 | 4,906 | 15 | 0.31% |
| A18 鑷子頂 | 4,388 | 8 | 0.18% |
| A20 高價配 | 1,638 | 3 | 0.18% |
| **合計（支持空單側）** | **66,812** | **177** | **0.26%** |

### 1.4 影響路徑（已逐行追蹤，非推測）

```
時段第一根誤觸發
  -> v_KB_Block = True
  -> v_Clean_Age 落入 ( v_Bars_In_Sess <= 1 ) 分支 = 999
  -> Mode 2: v_Filt_Pass = ( 999 <= KB_Filter_Win ) and ... = False
  -> 真實進場被擋掉
```

**下游 `v_Bars_In_Sess <= 1` 只重置年齡計數器，不阻止誤判產生。**

### 1.5 修正

三個家族入口各加一道閘門（所有型態都至少要兩根，
三根以上的既有 `>= 3/4/5` 閘門更嚴，不受影響）：

```powerlanguage
if v_KB_Sup = True and v_Bars_In_Sess >= 2 then begin
if v_KB_Opp = True and v_Bars_In_Sess >= 2 then begin
if v_KB_Neu = True and v_Bars_In_Sess >= 2 then begin
```

**三行改動涵蓋全部 28 種。**

## 3. ✅ U7 結案 — `MaxBarsBack` 到底是什麼

### 3.1 用戶給的定義

> 「『策略運算最大使用 K 棒數量』的定義是先系統內部跑 X 根後，
> 　才會實際開始有回測交易筆數，我目前都是設定先跑 100 根。」

**它是 MC12 圖表屬性，暖機需求，`.pla` 檔內沒有這一行 —— 刪不掉也不該刪。**

### 3.2 它不是「白痴設計」

| | K 棒濾網組態 | `MaxBarsBack` |
|---|---|---|
| 怎麼定的 | 看 180 筆損益挑出來 | 機械需求：回看 N 根就必須 ≥ N |
| 換資料會不會變 | 會 | 不會 |
| 診斷 | ❌ 結果變數選擇 | ✅ **正當** |

### 3.3 但舊文件是錯的，已修

`BACKTEST_COST_SPEC.md §4` 舊版寫「餘裕僅約 9 根」，依據 `ML_ATR_LongLen = 90`。
**該模組已移除。v1.26.0 最深回看是 `Struct_Lookback = 20`，餘裕約 80 根。**

已重寫該節（4.1–4.5），並記錄調高代價：

| 100 → | 多燒暖機 | 佔全資料 418,096 根 |
|---|---|---|
| 400 | 300 根 | **0.07%** |

**代價可忽略。圖表型態需要幾根就設幾根，不當約束。**

### 3.4 我上一則的錯誤結論已作廢

> ❌ 「99 根塞不下頭肩頂，所以複合頭肩頂不可實作」

**那個推理拿一個未查證的數字當硬約束，砍掉了一整批型態。**

## 4. 跨時段的進場判定 —— 兩類型態，兩套規則

用戶提的兩個情境：

- **情境 A**：收盤前兩根建立型態基礎，第三根是開盤當根
- **情境 B**：收盤前一根建立基礎，第二、三根是開盤當根與其後

**答案取決於型態類型：**

| 型態類型 | 可否跨時段 | 理由 |
|---|---|---|
| **相鄰依賴型**（吞噬、孕線、鑷子、三隻烏鴉…） | ❌ **不可** | 定義要求 `bar[0]` 與 `bar[1]` 貼合，隔 3h45m 就不是吞噬 |
| **擺盪幾何型**（頭肩、三角、旗形、雙頂…） | ✅ **可以** | 描述轉折結構的弧線，不看相鄰貼合 |

**用戶裁示：「是最好的判斷。」已依此修正程式碼（§1.5）。**

## 5. ★ 日級別認知誤區 —— 用戶的核心洞見

> 「本身就不要有日級別的策略思維，
> 　而是要把操作週期(5M)本身就當作是日級別的 K 棒型態。」

### 5.1 量化支持

| 週期 | 一根涵蓋 | 相鄰兩根之間的斷點 | 斷點佔比 |
|---|---|---|---|
| 日線 | 6h30m 交易 | **17h30m** 隔夜 | **72.9%** |
| 5 分 K（盤中） | 5m | 0 | 0% |
| 5 分 K（跨 13:45→15:00） | 5m | 1h15m | 93.8% |
| 5 分 K（跨 05:00→08:45） | 5m | 3h45m | 97.8% |

**日線頭肩頂天天跨越 72.9% 的斷點，沒有人因此重置它。**

### 5.2 誤區稽核結果

| # | 位置 | 誤區 | 裁示 |
|---|---|---|---|
| 1 | 代碼 1–5 / 14–18 / 27–28 | 把跨時段兩根當連續 | ✅ **已修**（§1） |
| 2 | 「99 根塞不下頭肩頂」 | 拿日線的型態長度慣例當 5M 的約束 | ✅ **已作廢**（§3.4） |
| 3 | `BACKTEST_COST_SPEC.md §4` | 描述已移除的模組 | ✅ **已重寫** |
| 4 | `MaxHoldingBars = 24` | 是否為日級別持倉假設？ | ✅ **用戶裁示：時間性質假設，非日級別結構。結案** |
| 5 | `Tail_DayNoEntry_From = 1335` | 是否為日級別思維？ | ✅ **用戶裁示：真實時段規則，控制在期貨收盤前。結案** |
| 6 | **`ATR_Len = 14`** | Wilder 1978 為**日線**設計，可能無腦沿用 | ⏳ **用戶裁示：需重新深度探討** |
| 7 | **`Struct_Lookback = 20`** | 同上 | ⏳ **待探討** |

### 5.3 ★ 我的認知誤區有共同結構 —— 記錄下來作為檢查規則

**三次誤區都是：把一個「觀察到的統計」當成「定義」。**

- 「頭肩頂要 40–120 根」→ 那是日線的觀察，不是頭肩頂的定義
- 「MaxBarsBack 餘裕只有 9 根」→ 那是舊模組的觀察，不是現況
- 「`n >= 50` 才算樣本足夠」→ 上一輪抓到的同一種病

**檢查規則（納入本專案紀律）：**

> **每當寫下一個數字當成約束，必須先回答：
> 　這個數字是「定義」、「量測」、還是「抄來的慣例」？
> 　抄來的慣例不得當成約束。**

**下一個要套用這條規則的對象就是 `ATR_Len = 14`。**

## 6. ✅ 型態失效條件 —— 零自由參數解

### 6.1 用戶指出的過度擬合風險

> 「設定 N 的參數，就會變相對於未來實戰上產生潛在的過度擬合風險，
> 　因為是單純參考一個最佳化後的定值。」

### 6.2 採用的解法（用戶裁示）

> **一個型態的有效期 = 它自己形成所花的根數。**

- 花 12 根形成的三角形 → 有效 12 根
- 花 47 根形成的頭肩頂 → 有效 47 根

**自由參數 = 0**，且自動適應週期與波動 ——
**震盪盤型態形成得慢，有效期自動變長**，正好對應用戶說的「除非今天是震盪盤」。

### 6.3 三種失效條件並存，全部零參數

| 失效方式 | 條件 | 參數 |
|---|---|---|
| **價格破壞** | 收盤越過型態自身關鍵位（頭部／較高峰／上緣線） | 0 |
| **時間衰減** | 存活根數 > 形成根數 | **0（自我指涉）** |
| **反向型態** | 出現反向的已確認型態 | 0 |

### 6.4 ⚠️ 持續性架構會改變「哪些型態能作動」

**現行：28 種必須恰好在進場那根完成 → 11 種多方型態永不作動（斜率閘門保證黑棒收尾）。**

**改成持續性後：**

1. **11 種多方型態全部復活**（可在 bar[-3] 完成，bar[0] 進場時仍有效）
2. **下降之鷹復活**（同理）
3. **`S16S_kbar_pattern_spec_20260816.md` §7.5 那張表全部作廢**（在「當根完成」架構下算的）
4. **`v_KB_Code` 先中先停級聯要改**：從「單一代碼」變成「多個並存的狀態旗標」

**第 4 點是實作上最大的改動。**
