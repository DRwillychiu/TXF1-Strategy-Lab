## 2. 為什麼不是「改個字串」那麼簡單

L1 v32 的 `TL_ReEntry` 是**獨立的第二條進場語句**，本來就有自己的標籤。

L2–L5 **只有一條進場語句**：

```powerlanguage
L2:  SellShort( "TS_Entry" ) Next Bar at Market
L3:  Buy ( "CL_Entry" ) next bar at v_Box_Btm Stop
L4:  SellShort( "CS_Entry" ) ...
L5:  Buy ( "BL_Entry_Bot" ) next bar at v_Box_Btm Stop
     Buy ( "BL_Entry_Mid" ) next bar at v_Mid_Line Stop
```

二次進場是**同一條語句再次觸發**。要掛不同標籤，必須有執行期條件分流：

```powerlanguage
If <這筆是二次進場> Then
    SellShort( "TS_ReEntry" ) ...
Else
    SellShort( "TS_Entry" ) ...
```

而 `<這筆是二次進場>` 需要策略「記得上一筆的結果」—— L2–L5 目前完全沒有追蹤這個狀態。

### 實作方式：手刻，不用未驗證的內建

repo 內建函式使用實測：

```
PositionProfit    0 個檔案使用
BarsSinceExit     0 個檔案使用
ExitPrice         0 個檔案使用
BarsSinceEntry    11 個檔案使用   <- MC 內建確實可用
```

**L4 自己手刻了 `v_BarsSinceExit`**（`L4:338, 527-531`），沒有用內建。
這代表那些內建在 MC9 的可用性未經本專案驗證。依物理證據原則，
**照 L4 已證明可行的方式手刻**，約 8–12 行 / 每支。

## 4. 需要裁決的定義：什麼算二次進場

**這不是技術問題，是定義問題** —— 而定義決定報表上哪幾筆被標記。

以 L3 為例，同一批交易在不同定義下的結果：

```
前一筆虧損停損 + <=150 分   ->   23 筆，  −64,000
前一筆虧損停損 + <=300 分   ->   27 筆，  −22,400
前一筆虧損停損 + <=1 天     ->   73 筆， +238,000
前一筆虧損停損 + <=3 天     ->  101 筆， −198,800
```

**四種答案，其中兩種正負號相反。**

### 4.1 建議：定義 A（無時間窗）

```
v_IsReEntry = 前一筆是「虧損停損出場」
```

理由：

1. **零個任意參數**。150 還是 300 分沒有客觀依據，那是後見之明挑的。
2. **不損失資訊**。報表有進出場時戳，時間間隔隨時可事後計算。
   **先標記事實，分析留給分析。**
3. **時間窗一旦寫進程式碼，就再也研究不了不同窗口** —— 標籤已經替你選好了。
   若硬選 <=150 分，L3 那 73 筆裡有 50 筆會被標成「一般進場」，
   而它們其實是同一個行為。

### 4.2 附帶待確認：「虧損出場」的範圍

| 選項 | L2 為例 |
|---|---|
| **只算停損**（建議） | `TS_TSL_*` / `TS_InitSL_*` 且損益 < 0 |
| 所有虧損出場 | 再加上 `TS_StructureTP` / `TS_TTP` 等虧損收場者 |

建議只算停損：「被打出去了再進」與「主動獲利了結後又進」是不同的行為。

## 5. 貼標籤後，實戰上會怎麼應對

### 第一層：下單行為 —— 完全不變

同樣的條件、價格、時點、口數。實戰上不會感覺到任何差別。

### 第二層：即時監控 —— 看得見「這是重進的」

MC 的訊號名會出現在委託單與策略績效裡。現在只會看到 `TS_Entry`；
改完之後 `TS_ReEntry` 會直接顯示。

**實戰意義**：連續三筆都是 `TS_ReEntry`，代表策略正在反覆接同一個失敗訊號 ——
那是**手動介入（Kill Switch）的判斷依據**。現在這個資訊看不到。

### 第三層：對帳 —— 這是本案的主要目的

訊號名會出現在券商回報與 MC 委託紀錄裡，所以標籤讓
**回測的二次進場**與**實盤的二次進場**可以逐筆對上。

沒有標籤就對不起來 —— 只能靠時間戳猜，而 §4 已示範猜的定義一改，
L3 的數字就從 23 筆跳到 101 筆、正負號都會翻。

### 第四層：⚠️ 驗證期副作用

`docs/research/optimization_survivors_20260718.md:13` 原文：

> L1-L5 正在 6 個月實戰驗證期。**驗證期中改 .pla = 實驗中途換受測物，驗證作廢重來。**
> 唯一例外：風控強制介入（熔斷已觸發 = 義務）。
> live_simulation 四隻（S1/S3_L/S3_S/S16_S）同理：改一行 code = 30 筆模擬門檻重新計時。

**規則寫的是「改 .pla」，沒有區分「改行為」還是「改標籤」。**
加標籤不屬於明訂的唯一例外。
