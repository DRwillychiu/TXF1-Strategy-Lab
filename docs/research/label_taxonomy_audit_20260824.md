# 訂單標籤稽核：五支 live ＋ S16_S（2026-08-24）

**觸發**：用戶提問「L2 與 L4 雖然都有二次進場，是不是標籤沒有標示清楚？」
**答案：是。而且今天我對 L2（22 次）與 L4（8 次）的二次進場，全部是「推論」出來的，不是讀出來的。**

---

## 0. 一句話

> ## **能不能「量」一個機制，取決於它有沒有自己的標籤。**
> ## **L1 v32 與 S16_S 我能直接讀；L2 與 L4 我只能從時間戳和價格猜。**

---

## 1. ⚠ 先修正一個判讀錯誤

我第一版用「勝率介於 15%~85% 就算標籤混用」當啟發式。**那是錯的，會把兩種完全不同的東西混為一談：**

| 情況 | 例子 | 判定 |
|---|---|---|
| **一個標籤 ＝ 兩個不同機制** | L4 `CS_SL` ＝ 移動停損 **或** 凍結初始停損 | **✗ 真缺陷** |
| 一個標籤 ＝ 一個機制，但賺賠都有 | `CS_TimeExit`、`CL_BreakExit`、`BL_TimeExit_Mid` | **✓ 完全正常** |

**時間到就走、箱體破了就走——本來就會賺也會賠。那不是標籤問題。**

**以下改用程式碼判定：追出場價位變數有幾個賦值來源，對照它有幾個標籤。**

---

## 2. 進場側：**五支 live 沒有一支能從標籤讀出二次進場**

| 策略 | 進場標籤 | 能否讀出二次進場 |
|---|---|---|
| **L1 live** | `TL_Entry` | **❌** |
| L1 v32（research，未部署） | `TL_Entry` / **`TL_ReEntry`** | ✅ |
| **L2** | `TS_Entry` | **❌ —— 但實測有 22 次** |
| **L3** | `CL_Entry` | **❌** |
| **L4** | `CS_Entry` | **❌ —— 但實測有 8 次** |
| **L5** | `BL_Entry_Bot` / `BL_Entry_Mid` | **❌**（那是兩條進場路徑，不是一次/二次） |
| **S16_S** | `SE_MA_DeathCross` / **`SE_MA_ReEntry`** | **✅** |

### 2.1 這件事今天的實際代價

| 策略 | 我怎麼得到二次進場的數字 | 可靠度 |
|---|---|---|
| **S16_S** | **讀標籤** `SE_MA_ReEntry` → 7 筆、勝率 57.1%、+152,400 | **精確** |
| **L1 v32** | **讀標籤** `TL_ReEntry` → 11 筆 | **精確** |
| **L2** | **推論**：前一筆為虧損停損 **且** 新進場價 ≤ 舊進場價 → 22 筆 | **需要假設** |
| **L4** | **推論**：出場到下次進場的時間間隔 → 8 筆 | **需要假設** |

**L2 那 22 筆的間隔從 60 分鐘到 34 天都有。** 長間隔的那幾筆更像「下一個獨立訊號剛好更低」，
**我在文件裡把這條保留意見寫進誠實聲明——因為我沒有標籤可以確認。**

**同一個問題在 S16_S 不存在。**

## 3. 出場側：一個價位變數，幾個機制，幾個標籤

**判定方式**：找出下單語句用的價位變數，數它在程式中有幾個賦值來源。

| 策略 | 標籤 | 價位變數的賦值來源 | 有幾個標籤 | 判定 |
|---|---|---|---|---|
| **L2** | `TS_TSL_D` / `TS_InitSL_D`<br>`TS_TSL_N` / `TS_InitSL_N` | `Active_SL` ← 移動停損 或 初始停損 | **4**（機制 × 日夜） | **✅ 全庫最佳** |
| **L1** | `TL_SL` / `TL_SP` / `TL_TP` / `TL_TSL`<br>＋ `TL_SL_Gap` / `TL_SP_Gap` | `Final_Exit_Price` ← 三個價位取 `MaxList` | **6** | **✅ v2.9.1 已解決** |
| **L3** | `CL_BE` / `CL_SL` | `v_Work_SL` ← `v_Frozen_SL` / `v_Box_Btm−buffer` / `v_SL_Pct_Floor` / BE | **2** | **⚠ 部分**（`CL_SL` 三合一） |
| **L4** | **`CS_SL`** | `v_Effective_Stop` ← `v_Stop_Level`（**移動停損 或 凍結初始停損**）/ SP / BE | **1**（+CS_SP/CS_BE） | **❌ 最差** |
| **L5** | `BL_SP_Bot` ×3 站<br>`BL_SP_Mid` ×3 站<br>`BL_BE_Bot` / `BL_BE_Mid` ×2 站 | — | 標籤數 < 下單點數 | **❌ 同標籤多處發出** |
| **S16_S** | 13 個出場標籤，每個一處 | — | 13 | **✅** |

### 3.1 ⭐ L2 是全庫的模範寫法

```powerlanguage
If TSL_Armed = True Then
   BuyToCover( "TS_TSL_D" ) Next Bar at Active_SL Stop
Else
   BuyToCover( "TS_InitSL_D" ) Next Bar at Active_SL Stop;
```

**同一個價位變數，但用機制旗標分流標籤。** 報告上就能直接分開移動停損與初始停損。

### 3.2 ❌ L4 是全庫唯一沒做這件事的

```powerlanguage
v_Effective_Stop = v_Stop_Level;   { 這可能是移動停損，也可能是凍結初始停損 }
...
BuyToCover ("CS_SL") next bar at v_Effective_Stop Stop;
```

**沒有依 `v_Trail_Active` 分流。而 `v_Trail_Active` 是現成變數。**

**代價（今天實際發生的）：**

| 次數 | 我怎麼錯的 |
|---|---|
| **第 1 次**（08-22） | 把 `CS_SL` 讀成「停損桶」。實際 **71% 勝率、+1,781,200，是贏家桶** |
| **第 2 次**（08-24） | 要量移動停損時，只能**用損益正負去猜**（贏家必為移動停損，因為凍結停損掛在箱頂上方必虧） |

**34 筆 = L4 的 43% 交易，標籤說不清楚它是哪個機制帶走的。**

**L1、L2、L3 都有分流。L4 是唯一沒有的。**

## 4. 建議的規則（可被腳本檢查）

> ### **規則 L-1：一個出場價位變數若有 N 個機制來源，該出場就必須有 N 個標籤，依設定它的機制旗標分流。**
>
> ### **規則 L-2：同一個標籤不得從多個下單語句發出。**
>
> ### **規則 L-3：進場若可能來自不同觸發路徑（一次 / 二次 / 不同結構），每條路徑必須有自己的標籤。**

**三條都可以寫成 `scripts/verify_order_labels.py`：**
解析每個 `Buy/SellShort/Sell/BuyToCover( "label" ) ... at <var>`，
回追 `<var>` 的賦值站點數，與標籤數比對。

## 5. 修法與代價

**改標籤不改任何交易行為——但它會改變報告。**

| 影響 | 說明 |
|---|---|
| 交易筆數 / 損益 / 回檔 | **完全不變** |
| MC12 報告 | **出場標籤欄會變** |
| `compare_mc12_reports.py` | 閘門 [3] 會把純標籤改動判成「交易分歧」（它比對 `entry_sig` / `exit_sig`）→ **需要一個忽略標籤的模式** |
| live 策略 | **6 個月驗證期中，改 .pla = 驗證重來**（既有規範） |

**所以順序只能是：research 先改 → 錨點證明「只有標籤變，筆數與損益一格不差」→ live 何時換由你裁示。**

| 順位 | 對象 | 為什麼 |
