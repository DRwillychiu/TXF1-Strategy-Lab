## 2. 績效部分：完全無法呈現

### 2.1 缺失的項目（全部）

| 類別 | 缺失內容 |
|---|---|
| 損益 | 淨利、毛利、毛損、平均獲利/虧損 |

| 執行 | 滑價假設、手續費/稅、成交價假設（IOG？收盤價？） |
| 規模 | 總資金、口數規模（僅颶風揭露 2 口）、9 支之間的相關性 |

### 2.2 這代表什麼

1. **「已上架且賺錢」是口頭聲明，不是驗證過的事實。** 我這邊沒有任何可核對的物理證據。
2. **不能排序、不能挑選。** 沒有績效就無法判斷哪一支值得優先參考。
3. **不能抄參數。** 就算給了參數，沒有績效也不知道那組參數是否經過過度最佳化。
4. **可以抄的只有「機制概念」。** 這就是 §4 的全部內容。

### 2.3 一個需要注意的推測

⚠️ **推測（非事實）**：這 9 段描述的行文風格——星座 + 詩人的命名體系（摩羯座/天鷹座 + 伯牙/宋之問/楊炯）、伯牙那段的「甚麼時候對策略不利／甚麼時候觸發停利停損」問答格式——**讀起來像訂閱制程式交易平台的商品說明頁**，而非內部研發文件。

若此推測成立，則：
- 描述是為銷售而寫，會強調優點、淡化弱點（實際上 9 支只有 1 支揭露弱點，符合此模式）
- 「已上架」可能指「已在平台上架供人租用」，而非「已用自有資金實盤運行很久」
- 「賺錢」的樣本期間可能很短，或來自回測

**這一點必須向同事確認**，因為它決定了這批邏輯的參考權重。

## 4. 立即可用的資訊（依價值 × 可執行性排序）

### S 級：立即可做、高價值、不違反鐵律

#### S-1. 加碼機制：把平鋪 2 口改成 1+1 確認加碼

| 項目 | 內容 |
|---|---|
| 來源 | 颶風「具備加碼進場機制，在延續性強的大波段行情中有極高的爆發力」 |
| 我方現況 | L1–L5 全部平鋪 2 口（`L1_TrendLong.pla:119,523` / `L2_TrendShort.pla:50` / `L3_ConsolidationLong.pla:42,69` / `L4_ConsolidationShort.pla:211` / `L5_BreakoutLong.pla:187`）；10 支無任何加碼機制 |
| 為什麼值得做 | 1 口進場 + 1 口確認後加碼 = 同樣 2 口上限，但**輸的時候只有 1 口被停損（小賠），對的時候滿倉（大賺）**。直接命中目標損益型態 |
| 為什麼安全 | 加碼是**進場端**機制。鐵律「進場品質 > 持倉保護」與「出場端保護三次陣亡」的禁區都在出場端，這一項在允許的那一側 |
| 立即動作 | 拿 **L5** 做 A/B（它已有 scale-out TP，架構最接近）：平鋪 2 口 vs 1+1 加碼，比較大賠筆數與大賺幅度 |
| 前置檢查 | 先解決 §5 的口數文件矛盾（S16_S 兩份現行文件互相衝突） |
