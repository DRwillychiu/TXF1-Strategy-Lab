### 2.9 日盤尾盤規則 —— 一個從沒有人決定過的缺陷

v1.18.0 的閘門是 `v_Tail_Entry_OK = ( Time <= v_Tail_Cutoff or Time > 500 )`。

於是 1335 的訊號會在 1340 成交，**收盤前 5 分鐘進場，然後抱著過 1345–1500 休息，
期間沒有任何出場機制能動作**。

**但實測說的是反話：**

|---|---|---|---|---|
| 跨越 1345–1500 休息 | 7 | +308,800 | **+44,114** | **71.4%** |
| 純日盤 | 82 | +398,400 | +4,859 | 28.0% |
| 夜盤進場 | 93 | +1,345,600 | +14,469 | 32.3% |

## 3. ★ 兩個必須帶著走的教訓

### 3.1 MC12 最佳化器看不到 `TrueFalse` 型 input

**不是難掃，是完全不出現在最佳化清單裡。**
B1 和 B2 是在**沒有它們的開關**的情況下跑的 —— 報表各只有 3 個參數欄，
而不是規格書寫的 6 個和 4 個。那些開關不是「被選擇性凍結」，是**被排除**。

**v1.21.0 的修正**：17 個布林 input 改為數值 0/1，在 `SECTION 2.5` 解碼成布林鏡像變數。
下游只改識別字，仍比較 `True` / `False`。

> **為什麼不直接把 `= True` 改成 `= 1`**：re-entry 鏈有三個 `= False or` 閘門。
> 機械式取代很容易把 `= False` 寫成 `= 1`，邏輯**靜默反轉** —— 回測照跑、結果全錯。
> 包裝變數讓那三行只換名字、不動邏輯，陷阱從根上消失。

`Manual_Kill_Switch` 不轉：緊急營運開關，人在壓力下翻的東西，True/False 下拉不會弄錯、1/0 會。

### 3.2 時間類參數的 `TimeToMinutes()` 陷阱

```powerlanguage
v_Tail_Cutoff = MinutesToTime( TimeToMinutes( Tail_NoEntry_From )
                               - Tail_Signal_Lead_Bars * BarInterval );
```

`TimeToMinutes(t) = int(t/100)*60 + mod(t,100)`。**非法時鐘時間不會被拒絕，會被靜默重新詮釋：**

| 輸入 | 讀起來像 | **實際等於** |
|---|---|---|
| 365 | 03:65（不存在） | 3×60+65 = 245 分 = **04:05** |
| 380 | 03:80 | 260 分 = **04:20** |
| 395 | 03:95 | 275 分 = **04:35** |

B3b 的網格同時含這三個，**看起來均勻、實際跳躍**。

**兩條規則**：
1. 採用值必須是**合法時鐘時間**（415 = 04:15 ✓）。寫成 365 的檔案，半年後沒人推導得出來
2. 日後所有時間類參數的掃描步進，必須讓每一格都落在 **00–59 分**內（步 5／10／15 從 :00 或 :30 起跳）

另註：`Tail_Signal_Lead_Bars = 2` 會再往前扣 10 分鐘，所以 415 的**實際訊號截止是 04:05、成交截止 04:10**。

## 8. 保留意見

1. **績效起點是 748,000，不是 3,098,400。** 採用 Form 2 是**公式正確性**的裁示。
   即使全部調完也不保證回到 300 萬。這一點必須隨版本攜帶，**不可事後被重新詮釋成「最佳化的成果」**。

2. **`QuickStop_Loss` 的訂單型態缺陷未解。** 價格條件（`QS_MaxLoss_Pct`）卻用市價單，
   MAE 中位 −30,000（0.33%）穩定超出 0.25% 門檻，37/38 筆超穿。
   **參數掃描修不了這件事**，改 stop 單是獨立的程式碼改動。
   B4 掃出來的最佳 `QS_MaxLoss_Pct` **會混入這個滑移，須標註**。

3. **`ZLEMA_Fast/Slow` 改動會改變死叉集本身**，與 `MinSlope_Rate` 耦合。
   本計畫用座標下降 ＋ B13 回圈處理，這是**近似解不是聯合最佳解**。
   聯合最佳解在 6.4 年樣本上必定過擬合，**刻意不做**。

4. **零 OOS 資料剩餘。** 這策略已在 2020–2026 全樣本上做過約 25 個選擇，本 campaign 再加。
   Form 2 讓年度分布第一次成立（2021 從 0 筆變 13 筆、2023 從 0 筆變 2 筆），
   **切 holdout 在技術上第一次可行** —— 尚未執行，B13 之後再議。

5. **Rule #13 十維度 ／ Rule #18 五件套 ／ W4 WFA 全部未跑。** 這些是 PROMOTE 的前置，不是本 campaign 的範圍。
