# 圖形型態研究流程 — 效率檢視

**日期** 2026-08-26　**起因** 用戶：「進度其實偏慢，客觀檢視是否可以提高效率。」

---

## 0. 結論先講

**慢的主因不是討論太多，是「母體定義沒有一次定死」，導致同一批下游統計重算了五次。**

```
P29 母體數字的演變

  1,119   原始 §2（只要求單調外擴）
    111   ＋ 樞紐必須交替                    -90.1%
     85   ＋ 低點在高點下方 ＋ 同一時段
    172   偵測改為對稱掃描                   +102%
    202   移除「同一時段」（那是 K 棒規則，套錯了）  +17.4%
```

**每換一次，三向細分、跨度、逐年、時段、S1 分數全部要重算。**
純量測工時被乘了五倍，而每一次改動的**理由都成立** —— 問題不在裁示，
在於這五個問題**不是在同一個時間點被問出來的**。

## 2. 三個具體浪費，附數字

### 浪費一：母體重定義五次 -> 下游統計重算五次

**代價**：三向細分、跨度分布、逐年、時段、S1 分數 × 5 輪。

**解法：型態定義檢查表**（§4），規劃階段一次問完。

### 浪費二：13 支腳本各自重讀 32 MB CSV，其中 6 支各自重算樞紐

```
13 支腳本讀 s16s_5min.csv
 6 支各自重算 151,177 個樞紐
```

**代價**：每次改定義，六支都要改、都要重跑，而且**改漏一支就出現不一致的數字**
（2026-08-25 就發生過：`s16s_p29_find_example.py` 的篩選條件與 `_clean.py` 不同步）。

**解法：共用資料層**（§5）。

### 浪費三：我用「論證」而不是「量測」提建議

**自承**：裁示 12 的 commit 訊息寫著 ——
> 我先前建議用斜率，理由是「它用到全部十二根、抗雜訊」。
> **那是論證，不是證據。** 結論站得住，但支撐它的推理現在才有量測。

**代價**：先給了一個沒有數字的建議，用戶接受後又得回頭補量測；
或用戶不接受，來回一輪。

**解法**：任何選項比較，**先跑數字再開口**。這條寫進 §6 紀律。

## 3. 但有一件事本來就不該省

**「先畫出來才知道哪裡有問題」不是浪費，是這條流程最有價值的一步。**

四個缺陷裡有三個是「畫出來或被追問」才浮現的，
**規格文字上完全看不出來**。省掉這一步，缺陷會留到 `.pla` 裡，
到時候是回測數字錯，不是圖難看。

**要提效的是「把缺陷一次問完」，不是「少畫幾張圖」。**

## 4. 型態定義檢查表（規劃階段一次問完）

從 P29 的四個缺陷反推。**P49-P54 與後續所有型態，規劃階段逐條回答。**

### A 樞紐層

1. 樞紐用什麼定義？視窗幾根？
2. **樞紐是否必須交替？** 不要求的話會不會出現兩條線交叉？
3. 樞紐偵測要不要跨時段？（**分形是相鄰依賴 -> 不跨**）
4. 粗尺度穩健性要不要？當濾網還是當屬性？

### B 型態層

5. 需要幾個樞紐？高低是否對稱要求？（3+2 是陷阱）
6. **有沒有幾何一致性要求？**（低點須在高點下方之類）
7. **型態本身能不能跨時段？**（**擺盪幾何 -> 可以跨**，別把 K 棒規則套過來）
8. 有效期怎麼定？

### C 偵測層

9. **偵測是否對稱？** 有沒有錨定單側而漏掉另一半排列？
10. 排列順序有幾種？兩種的行為一樣嗎？

### D 方向／分類層

11. 方向量法會不會被「收尾樞紐型別」污染？
12. **有沒有跑虛無對照？**（不加型態要求時，這個量法的基準差距多少）
13. 分類要不要把混淆因子攤開？

### E 顯示層　★ 2026-08-26 新增

14. **這個型態在圖上怎麼被找到？**（平均幾根出現一次？需不需要 locator？）
15. **偵測與顯示是否同一輪驗收？**

**第 14、15 條是今天加的** —— P29 偵測驗收 202/202 之後才發現肉眼認不出來，
顯示又多花了三輪除錯。**偵測與顯示應該同一份規格。**

## 5. 共用資料層

**現況**：13 支腳本各自讀 CSV，6 支各自算樞紐。

**改成**：

```
scripts/research/s16s_pivots.py      -> s16s_pivots.json    （一次算完，含視窗 1/2）
scripts/research/s16s_patterns.py    -> s16s_patterns.json  （所有型態，含屬性）
其餘腳本只讀 json，不碰 CSV，不重算樞紐
```

**效益**：定義一改只改一處；不可能再出現兩支腳本數字不一致。
