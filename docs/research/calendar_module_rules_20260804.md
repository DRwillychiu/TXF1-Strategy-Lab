## 一、架構決策（本手冊最重要的一條）

### D-1：採「產生期共用」，不採「執行期共用」

**決策**：單一資料源（TAIFEX 驗證過的日期表）→ Python 產生器產生各 `.pla` 內嵌區塊 → 驗證腳本斷言所有副本與資料源一致。

**否決的方案**：PowerLanguage User Function（執行期共用）。

**否決理由（依嚴重度排序）**

1. **失效模式是靜默的。** MC 官方行為：修改 function 後必須每台機器執行 Recompile All，否則**已掛在圖上的策略繼續使用舊版**。這會產生「部分策略吃新表、部分吃舊表」的狀態，而畫面上看不出任何差別。對照本專案 2026-07-26 事故：`verify_pla_ascii.py` 回報 36/36 PASS、exit 0，實際掃了零支在役策略，靜默 9 天。**守門員的失效必須是吵的。**
2. **跨機器無法驗證。** 使用者有桌機（MC9 實盤）與筆電（MC12 開發）兩套環境。Recompile All 要在兩台各做一次，且**沒有任何事後驗證手段**能確認做了沒有。
3. **metadata 不進 git。** Function 的 Return Type / Function Storage / MaxBarsBack 存在 `TSSTORAGE.GDB`，**不在原始碼文字檔內**。git 同步 `.elf` 文字檔不足以還原一個可用的 function。
4. **覆蓋原始碼有陷阱。** 直接覆寫 `SrcEl\` 下的檔案，PowerLanguage Editor 不知道原始碼變了，會拿舊的 cpp transcode 去編譯。
5. **共同故障點。** 執行期共用把 Q1 的最壞情境實體化。產生期共用則讓每支策略在執行期仍持有自己的副本，**單點失效被移到產生期，而產生期正好是驗證器看得到的地方**。

**接受的代價**：假日表更新時需重新產生並在 MC 重載受影響檔案。但假日表更新頻率是**一年一次**（Q4 批次補次年），而 Function 方案的 Recompile All 是**每次修改都要、且不可驗證**。

**保留條件**：若未來 MC 提供「function 版本雜湊」或「編譯時戳查詢」使 stale 狀態可偵測，D-1 可重新評估。

### D-2：Settlement 維持動態偵測，不併入資料表

`docs/policies/settlement_flat_module_20260617.md` §九 已評估並否決靜態登錄表（Approach D），理由：第三週三規則 50 年不變、0 維護成本。**Settlement 與 Holiday 使用兩種架構是刻意設計，不是不一致，不得「統一」。**

Holiday 之所以必須是表，是因為農曆、行政補班補假、颱風臨時停市**無法演算法化**（`entry_exit_sop.md` §三之一 明載「殘餘風險（無法程序化）：颱風/天災臨時停市」）。

## 二、安全鐵則（違反任一 = 該方案否決）

### R-1：失效方向必須是 fail-safe

共用模組的任何失效，結果必須是「**全部空手**」而非「全部留倉」。這是既有 `Registry_Valid_Until` 的設計精神（超過登錄視界即封鎖進場 + 平倉），模組化不得削弱它。

### R-2：任何 `Time >=` 必須配對 `Time <=`

**WHY**：MC PowerLanguage 的 `Time` 是 24 小時制。`Time >= 1200` 在夜盤 15:00–23:59 全為 true。憲法條款 7/8 記載 L3 v13.3 / L4 v14.3 就是這樣炸的，最後整條回滾。

**邊界案例（必須處理）**：本專案現況有 **10 處未配對的 Settlement `Time >=`**，而且它們源自憲法**自己**——條款 1「元素 5」的參考實作（`SETTLEMENT_DAY_DESIGN_CONSTITUTION.md:75`）就是無上界寫法，卻在同文件第 234 行的 checklist 要求閉區間。**憲法自相矛盾，需先裁決哪一邊為準，再談模組。**

### R-3：Priority-0 順序不可更動

`Kill > Registry > Holiday > Settlement > 原策略邏輯`（憲法條款 3，「任何違反順序的策略 = 不可上架」）。

**現況違反**：L1、L3 的 Kill 寫成 else-if 鏈外的獨立 `if` 且排在最後。

**隱藏相依（重要）**：L1-L5 的 Holiday 出場雖無時間上界，實質安全靠的是「`v_Holiday_Block` 只在 `Time <= 500` guard 內才設 true」+「Registry 分支排在 Holiday 之前」兩者共同封死。**調換順序、或把 `else if` 拆成獨立 `if`，這個保護會立刻消失。** 模組化搬動順序時必須同步驗證此路徑。

### R-4：多腿策略每口一個標籤

憲法條款 4。**L5 的 Kill / Registry / Holiday / Settlement 四個分支全部有 `_Bot` + `_Mid` 兩個標籤，共 8 個**（L5:576-587），不只 Settlement。模組介面不得假設「一支策略一個標籤」。

### R-5：`Holiday_Flat_Time` 必須由 K 棒週期推導，不得手設常數

**WHY**：觸發時點必須落在該策略 K 棒週期的收盤網格上，否則條件永遠不成立。

**實證（本次發現的 bug）**：夜盤 15:00 起算的收盤網格 —

```
45M: 1545 1630 1715 1800 1845 1930 2015 2100 2145 2230 2315 0000 0045 0130 0215 0300 0345 0430
60M: 1600 1700 1800 1900 2000 2100 2200 2300 0000 0100 0200 0300 0400 0500
```

| 策略 | 週期 | 窗口 | 判定 |
|---|---|---|---|
| L1 | 45M | [345, 455] | ✅ 命中 0345、0430 |
| S1 | 15M | [415, 500] | ✅ 命中 4 點 |
| **S3_L** | **60M** | **[415, 455]** | ❌ **無任何命中 → 永不觸發** |
| S3_S | 1M | [415, 455] | ✅ |
| S3_RPS | 5M | [245, 455] | ✅（但設計上不可達，純日盤） |
| S16_S | 5M | [415, 500] | ✅ |

L1 的 `345` 精準落在 45M 網格上，且 `entry_exit_sop.md` §三之一 明載「L1 45 分 K = 03:45」→ 證明其他策略的值都是照網格推導的，**只有 S3_L 推錯**。其 `:120` 註解 `{ 60M grid -> fire 04:15 holiday tail }` 事實錯誤，04:15 不在 60M 網格上。

**模組的核心職責即此推導**：輸入 K 棒週期 → 輸出「保證收盤前歸零且留有一次重試」的最晚收盤點。S3_L 這個 bug 在該設計下不可能存在。

### R-6：禁止把 `>=` 精確化為 `=`

**WHY**：L2 是 60M，`Settlement_Flat_Time = 1230` **不在** 60M 日盤網格上（收盤戳記為 09:45/10:45/11:45/12:45/13:45），靠 `Time >= 1230` 在 **12:45** 那根觸發，仍早於 13:30 結算，保護有效。

若模組為「精確化」把 `>=` 改成 `=`，**L2 會當場失去結算保護**。這是 R-5 的鏡像案例：一個因 `>=` 而僥倖存活，一個因窗口過窄而死亡。

### R-7：退化錨點測試為必要條件

抽出模組後，在相同輸入下 10 支策略的 trade list 必須與現行**逐筆位元相同**。非零差異即代表接線錯誤，與參數好壞無關。

**已知的合法差異（必須事先豁免，否則會誤判為 bug）**：L5 的 Priority-0 目前巢狀在 `if v_is_in_consolidation`（L5:499 → 574 → 703）內，箱型消失時走 `else` 分支（L5:705-710）由 `BL_BreakExit_*` 無條件市價平倉兜底。模組化的標準動作是把 Priority-0 提到 gate 外（L3 即如此，`:445-461` 自稱 "always active"）。搬動後行為等價但**出場標籤會從 `BL_BreakExit_*` 變成 Priority-0 標籤**，此差異合法。

### R-8：母本必須選 L1 或 L2

**WHY**：L1/L2 保留 **9 個 `*` 標記**代表該日期「未經 TAIFEX PDF 驗證」；**L3/L4/L5 完全沒有這些標記**（L4:363 區段註解仍寫著 `* = reconstructed`，清單裡卻一個 `*` 都沒有）。

以 L3/L4/L5 為母本會**永久遺失「哪 9 筆未驗證」的資訊**，直接違反 `entry_exit_sop.md` §三之一「期交所 PDF 為唯一準據」的五步驗證程序。

### R-9：TAIFEX 官方 PDF 為唯一準據

`entry_exit_sop.md` §三之一：期交所「期貨集中交易市場行事曆」PDF 為唯一準據；政府行事曆 ≠ 市場行事曆。交叉檢核期貨商行事曆 + 人事行政總處公告，三源一致才寫入。

**本次未做**：兩份差異報告只做了 10 支策略**彼此之間**的一致性比對（結論：63 筆完全相同，md5 一致），**未與期交所 PDF 核對**。模組上線前必須補做。

### R-10：模組的適用範圍是 29 個檔，不是 10 個

含 `Holiday_Tail` 的檔案實測為 **29 個**（含 research 版本），非原估的 10 個在役策略。產生器與驗證器的涵蓋範圍必須以實際掃描結果為準，且比照 `scripts/strategy_discovery.py` 加上**覆蓋率斷言**（發現數 ≠ 處理數即 FAIL）。
