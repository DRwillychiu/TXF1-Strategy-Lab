## 1. 為什麼結案

### 1.1 L4 本來就會二次進場，而且是賠的

| 間隔 | 筆數 | 淨額 |
|---|---|---|
| ≤ 150 分（冷卻地板 + 2 根） | 5 | **−112,000** |
| ≤ 300 分 | 8 | **−95,200** |
| ≤ 1 天 | 14 | −148,800 |

**機制**：`CS_BreakExit` 之後價格再戳一次箱頂 → `v_In_Trap_Zone` 重新亮起 →
`Cooldown_Bars`（8 根 = 120 分）一過就再進場。

**8 次裡 7 次跟在 `CS_BreakExit` 後、1 次跟在獲利的 `CS_SL` 後。**
**跟在虧損停損後的：0 次。**

### 1.2 v18 想補的那條路，樣本上限只有 11

「停損後、價格回到原進場價」的候選事件，六年半只有 **11 筆**（`−518,000`，毛損的 28.9%），
分布 2020(1) / 2022(4) / 2023(3) / 2024(2) / 2025(1)，**2021 與 2026 掛零**。

**11 個事件在統計上不會給出決定性答案。** L1 的二次進場也是 11 筆，同一個天花板。

### 1.3 L4 真正的問題不在這裡

| 問題 | 數字 |
|---|---|
| Rule #13 交易頻率 | **七年只有 2022 一年達標**（2.50/月）；2024 是 0.33、2026 是 0.25 |
| 集中度 | **前 2 筆 = 99.7% 淨利**；其餘 77 筆合計 +2,800 |
| 回檔 | −789,200 = **帳戶 39.5%**（Rule #13 門檻 30%，Bootstrap 95% 為 47.0%） |
| 空窗 | **27 季有 11 季零交易**，最長持平 1 年 3 個月 |

**這些都不是二次進場能解的。**

### 2.1 零觸發的已知原因（未經 DIAG 證實）

凍結初始停損 = `箱頂 + 2 × ATR`，**結構上永遠在箱頂上方**。
被它帶走 → 價格必然穿過箱頂。而 DISARM 測的就是「Data2 收盤是否在箱頂上方」。

> **解除條件被停損本身蘊含。旗標在被設立的同一根就被清掉。**

**這與 L1 設計時抓到的陷阱同族**（`Close > 凍結突破線` 當狀態條件會讓機制永不觸發）。
**當時我在文件裡寫「L4 的幾何是乾淨的，不需要改」——那句話只檢查了觸發 vs 停損，沒檢查解除 vs 停損。**

**若日後重啟，修法方向**：DISARM 門檻改用**原始停損價**而非箱頂
（那條線本來就在箱頂上方，被停損不蘊含突破它，且不新增參數）。**未驗證。**
