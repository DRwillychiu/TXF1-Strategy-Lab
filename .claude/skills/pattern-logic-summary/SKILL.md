# 型態邏輯總整理格式規範

> **2026-08-25 用戶裁示**：「在未來只要討論完一個邏輯就完整呈現給我」
>
> **觸發時機：任何一個型態的逐一邏輯規劃完成之後，立刻產出，不等到全部做完。**

---

## 1. 在流程裡的位置

```
討論  →  逐一邏輯規劃  →  【本文件】  →  畫對照圖  →  HTML  →  才程式碼化
                            ▲
                     五段總整理 .md
```

**前一步沒完成不能寫這份**（不能拿還在討論中的東西寫成定稿）。
**這份沒產出不能往下走**（不能跳過總整理直接畫圖或寫程式）。

---

## 2. 五段格式 —— 段名與順序不可更動

| 段 | 段名 | 內容 |
|---|---|---|
| 1 | `# 標題` | 型態代號、中英文名、方向、根數、出現次數、自由參數、流程位置、規格全文路徑 |
| 2 | `# 重點說明` | 一句話白話定義 ＋ 與相近型態的分界 ＋ **所有實測數字** ＋ 為什麼這樣定義 |
| 3 | `# 圖形示意圖說明` | ASCII 示意圖 ＋ 讀圖重點 ＋ 變體外觀差異 ＋ 線上圖鑑連結 |
| 4 | `# 操作邏輯` | 盤面意義／用法／突破怎麼算／有效期／**目前不能做的事** |
| 5 | `# 程式碼邏輯` | 逐段 PowerLanguage 風格規格 ＋ 自由參數盤點表 ＋ 尚未完成清單 |

---

## 3. 每一段的硬性要求

### §1 標題

必含 8 個欄位：代號｜方向｜根數｜出現次數（含佔比）｜自由參數｜流程位置｜規格全文路徑。
**流程位置要逐項標 ✅／⏳**，讓人一眼知道走到哪。

### §2 重點說明

- **開頭必須是一句話白話定義**，不能直接進技術細節。
- **必須寫出與最相近型態的分界**（例：擴散 vs 三角＝兩條線往外開 vs 往內收）。
- **所有數字必須是實測的**，並標明母體大小。推估值一律標 `—`，不可填近似。
- **凡是「為什麼這樣定義而不是那樣」，必須附對照量測**，不可只給理由。

### §3 圖形示意圖說明

- ASCII 圖必須標出**關鍵點位的代號**（PH1／PL1 等），不能只是形狀。
- 必須寫「讀圖三個重點」之類的條列，指出**肉眼要看哪裡**。
- 有變體（上升／下降／水平等）就必須列出**外觀差異對照**。
- 附線上圖鑑連結。

### §4 操作邏輯

- 先講**盤面意義**（這個型態在描述市場什麼狀態），再講怎麼用。
- 突破／觸發條件的**每一個細節都要釘死並列表**，含「相等算不算」「影線算不算」
  「幾根確認」「要不要幅度門檻」「假突破撤不撤銷」這類容易留活口的地方。
- **必須有「⚠️ 目前不能做的事」小節**，寫明哪些話還不能講、哪些依據不能引用。

### §5 程式碼邏輯

- **開頭必須聲明「這是規格，不是已上線的程式碼」**，若 `.pla` 尚未寫入要明講。
- 逐段對應規格章節，段號一致。
- **必須有自由參數盤點表**，逐段列出，最後一列是合計。
- **必須有「尚未完成」清單**，把設計但未量測、未編碼、未檢定的部分逐條寫出。

---

## 4. 誠實要求（違反即作廢）

1. **不可把「設計」寫成「量測」。** 沒跑過的段落必須標「尚未實測」。
2. **不可引用未經用戶逐一審查的自訂定義所產生的檢定結果**作為設計依據
   —— 那是循環論證（2026-08-25 事故）。
3. **不可宣稱型態能改善進出場**，除非用戶已同意檢定且檢定已完成。
4. **數字必須可複現**，標明腳本路徑與資料母體大小。
5. **普查腳本一律無損益欄** —— 型態依「出現次數」與「能否零參數定義」盤點，
   不依「它賺多少」。

---

## 5. 檔名與位置

```
docs/research/S16S_<代號>_SUMMARY_<YYYYMMDD>.md
```

規格全文另存 `S16S_<代號>_logic_spec_<YYYYMMDD>.md`，**兩份都要**：
SUMMARY 是給人看的五段版，logic_spec 是完整推導與裁示紀錄。

---

## 6. 參考範例

`docs/research/S16S_P29_SUMMARY_20260825.md` —— P29 擴散三角，五段齊全，
自由參數 0，含三個決定性量測與一個明標的未完成缺口。
