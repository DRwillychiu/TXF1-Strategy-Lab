# 版本績效總表格式規範

> **2026-08-15 用戶裁示**：「不然根本不知道與前一版本優化了哪邊」
> 每次版本推進、每批最佳化採用之後，**都要更新這張表**，不是等到專案結束才整理。

---

## 1. 何時觸發

| 事件 | 動作 |
|---|---|
| 版本號推進（vX.Y.Z） | **必須**新增一列 |
| 最佳化批次採用（B1 / B2 / …） | **必須**新增一列 |
| 零改動的驗證批次（邊界檢查、退化錨點） | **必須**新增一列，Δ 標 `±0`，說明欄註明「N 格，零改動」 |
| 被否決的對照組（REJECTED / 未採用） | 新增一列，套用 `dim` 樣式，說明欄註明「未採用」 |
| 純註解 commit | 不新增 |

**零改動的批次一定要列。** 它們是這張表能被相信的原因 —— 讀者要看得出來
「這個值被挑戰過而站住了」與「這個值從來沒被測過」的差別。

---

## 2. 欄位定義與資料來源

一律取自 MC12 完整回測報告 xlsx 的 `策略分析` 分頁。**不可用最佳化報表的欄位混充。**

| 欄位 | xlsx 欄位名 | 格式 | 備註 |
|---|---|---|---|
| 版本 | — | `vX.Y.Z` 或批次代號 | 變體加副標（如 `無時間限制`） |
| 改了什麼 | — | 一句話，動詞開頭 | 副標放格數／證據等級 |
| 淨利 | `淨利` | 千分位 | 負值用 U+2212 減號 |
| **Δ** | 計算 | 與**上一列**的差額 | 斷點之後重新起算 |
| 獲利因子 | `獲利因子` | 4 位小數 | |
| 調整後獲利因子 | `調整獲利因子` | 4 位小數 | Rule #13 成本維度用 |
| 資本報酬率 | `初始資本報酬` | 百分比 2 位 | **不是** `帳戶報酬` |
| 年化 | `年報酬率` | 百分比 2 位 | |
| 最大回檔 | `最大策略虧損` | 千分位 | **不是**最佳化報表的 Max Intraday Drawdown |
| 回檔% | `最大策略虧損 (%)` | 百分比 2 位 | Rule #13 的 25% 門檻看這欄 |
| 夏普 | `夏普比率` | 4 位小數 | |
| 筆數 | `交易總次數` | 整數 | |

### 只有最佳化報表的批次

B 系列的中間批次通常只有最佳化報表（沒有完整 xlsx），該報表**沒有**調整 PF、年化、夏普。

**缺的欄位一律填 `—`，不可推估、不可留白、不可用最佳化報表的近似欄位頂替。**
表尾必須註明哪些列是這種情況。

> ⚠️ 最佳化報表的 `Max Intraday Drawdown` 與完整報表的 `最大策略虧損` **不是同一個量**。
> 混用會讓回檔欄位在表中不可比。同一欄只能放同一個定義。

## 3. 可比性斷點 —— 這是本規範的核心

**當一次改動使新舊母體不再是同一批交易時，必須在表中插入斷點列。**

判定門檻：用 `(日期, 時間, 進場價)` 配對，**共同進場數 < 舊版筆數的 70%** 即為斷點。

斷點列必須寫出三件事：

1. **改了什麼**（公式／機制的前後對照，寫出實際算式）
2. **重疊了幾筆**（配對比對的實測數字）
3. **一句禁止語**：「以下的淨利不可與以上直接相減」

**已知斷點：**

| 版本 | 內容 | 重疊 |
|---|---|---|
| v1.20.0 | `v_Slope = Fast[1] − Fast`（點數）→ `( Close[1] − Close ) / Close / 實際經過分鐘`（百分比／分鐘） | **28 / 118** |

### 斷點之後怎麼比

**只能比風險調整後的指標**（同資金、同成本結構下才有意義）：
調整後獲利因子、夏普、索丁諾、回檔%、帳戶所需金額。

**淨利、年化、資本報酬率跨斷點無意義**，因為那是兩支不同策略。

> 這條規則救過一次真實誤判：v1.22.0 的淨利比 v1.18.0 低 24.8%，
> 表面看是退步，但調整 PF ／ 夏普 ／ 索丁諾 ／ 回檔四項全部更好，
> 而且年度分布從「實質 2.5 年」變成「完整 6.5 年」。
> **只看淨利會把這半年最重要的一項改動判成失敗。**

### 夏普尺度斷點

v1.15.0 之前的夏普／索丁諾為不同計算基準（差三倍以上），**不得與之後並列**。
表尾必須註明。

## 4. 視覺約定

深色數據終端風格，單一主題（不做淺色版）—— 這是一張終端讀數，不是文件。

| 元素 | 規則 |
|---|---|
| 底色 | `#12151b` 頁面／`#1a1e26` 表格 |
| 數字 | 等寬字體 ＋ `font-variant-numeric: tabular-nums`，右對齊 |
| 版本欄 | 藍 `#6fa8dc`，粗體 |
| **重點列** | 金 `#f0a830` ＋ 10% 底色。**只給時代終點與現行版本**，不要超過 4 列 |
| 未採用／對照組 | `dim` 灰化 ＋ 紅色長條 |
| 淨利長條 | 寬度 ∝ 淨利，滿格 = 全表最高值。金＝重點列、紅＝未採用、灰＝一般 |
| Δ 欄 | 正綠 `#5fbf8f`／負紅 `#e0625c`／`±0` 灰 |
| 時代分隔 | 全寬 band 列，大寫字距標題 ＋ 一行說明 |
| 斷點 | 紅色上下框線 ＋ 7% 紅底，與時代分隔明顯不同 |

**重點列的節制**：金色是這張表唯一的強調色。四列以上就失去意義。

---

## 5. 表頭的摘要區

表格上方必須有一組 KPI 卡，比較**現行版本 vs 前一個時代終點**：

- 每張卡三行：舊值（灰、小）／新值（大、粗）／變化率（綠或紅）
- **風險調整指標若全部改善，那幾張卡標金色**
- 卡片下方一段 `note`，用一句話解釋「淨利下降不等於退步」的理由

這一區的作用是：**讓人在看細表之前就知道該用哪個角度讀它。**

## 6. 產出與位置

| 檔案 | 用途 |
|---|---|
| `docs/research/S16S_version_performance_table.html` | 視覺表，自足 HTML，無外部資源 |
| `docs/research/S16S_version_performance_history_YYYYMMDD.md` | 文字版，含推導、可比性限制、未解問題 |

**兩份都要更新，不可只更新一份。** HTML 是給人看的，md 是給搜尋與 diff 用的。

資料寫在 HTML 的 `const D = [...]` 陣列裡，一列一筆，**這個陣列就是規格本身** ——
改資料只動陣列，不動渲染邏輯。

---

## 7. 反模式

| # | 反模式 | 為什麼錯 |
|---|---|---|
| 1 | 跨斷點直接比淨利 | 兩支不同策略 |
| 2 | 缺的欄位用最佳化報表近似值頂替 | 同一欄兩種定義，全欄失效 |
| 3 | 零改動批次不列 | 讀者無法分辨「被挑戰過」與「沒測過」 |
| 4 | 只在專案結束時整理 | 當下的歸因資訊會遺失，事後補是猜的 |
| 5 | 金色重點列超過 4 列 | 強調色失效 |
| 6 | 只更新 HTML 不更新 md | md 是可 diff、可 grep 的那一份 |
| 7 | 混用 `帳戶報酬` 與 `初始資本報酬` | 前者以所需保證金為分母，會隨回檔變動 |

## 8. 檢查清單（每次更新後跑一遍）

- [ ] 新版本／新批次已新增一列
- [ ] Δ 欄相對上一列正確，斷點後重新起算
- [ ] 缺的欄位是 `—`，不是空白也不是推估值
- [ ] 若母體重疊 < 70%，已插入斷點列並寫出三件事
- [ ] 金色重點列 ≤ 4
- [ ] HTML 與 md 兩份都更新了
- [ ] 表尾註明哪些列只有最佳化報表欄位
- [ ] commit 訊息寫出這一列的增量與依據
