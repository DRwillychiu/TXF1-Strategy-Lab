## 三、Path B 失敗的根本原因

### BE 失敗（C/E）— L3 詛咒重演（變形版）

L3 變體 D 的失敗模式是：BE @ +50 pts 觸發後，箱體內反覆震盪會無限觸發 BE，最終 100 筆 0% 勝率。

L4 變體 C 的失敗模式 **不同但結果類似**：

| 維度 | L3 v13.2D | L4 v14.2C |
|------|-----------|-----------|
| 門檻 | +50 pts | +60 pts |
| 觸發後典型路徑 | 箱內反覆震盪 → BE 反覆觸發 | MFE 達門檻 → 第一次回檔即觸發 BE |
| 失敗機制 | 截斷區間內目標到價 | 截斷「多階段獲利」中的大尾巴 |
| CS_BE 勝率 | 0% | 0% |
| Top-10 影響 | — | **4/10 被斬首，-435,800** |

**Top-10 中被 BE 殺死的 4 筆贏家**（這是 L4 BE 失敗的鐵證）：

| 日期 | 時間 | A 結果 | A MFE | C 結果 | 損失 |
|------|------|--------|-------|--------|------|
| 2025-04-08 | 23:15 | CS_SL **+164,200** | +192,400 | CS_BE **-1,000** | **-165,200** |
| 2020-03-13 | 22:15 | CS_SL **+140,200** | +157,800 | CS_BE **-1,000** | **-141,200** |
| 2022-07-01 | 09:15 | CS_SL **+68,000** | +78,800 | CS_BE **-1,000** | -69,000 |
| 2022-04-26 | 09:15 | CS_SL **+59,400** | +65,600 | CS_BE **-1,000** | -60,400 |
| **合計** | | **+431,800** | | **-4,000** | **-435,800** |

這 4 筆都有「進場 → MFE 達 +60 → 回檔但未到 BE Floor → 繼續走深 → 大贏」的多階段獲利模式。**BE 在第一次回檔接近 BE Floor 時就觸發，把可能的大贏轉成 1K 小虧。**

### SP 失敗（D/F/G）— 100% 勝率反而是陷阱

CS_SP 看似完美：100% 勝率、22 筆全賺、+235K。但比較總出場分布：

| 出場類型 | A baseline | D (SP only) | 變化 |
|----------|------------|-------------|------|
| CS_SL | 45 / +1,019,200 | 36 / **+618,600** | **-401K** ⚠️ |
| CS_SP | — | 22 / +235,200 | +235K |
| 其他 | -437,000 | -485,000 | -48K |
| **總計** | **+581,200** | **+369,200** | **-212K** |

**SP 把 +1M 的 CS_SL 大尾巴贏家砍成 +235K 的保證小贏。** CS_SP 自己 100% 勝率，但代價是：
- CS_SL 平均 MFE +281 pts → 平均最終 +198 pts 的「真趨勢贏家」被提早收進口袋
- 失去尾巴讓利的紅利

**這是 L3 詛咒的變形版**：不是 0% 勝率，而是 **小贏家換大贏家** — 系統性虧損。

---

### Path B 的結構性問題（為何 BE/SP 對 L4 都不適用）

L4 的大贏家有 **多階段獲利模式**：
```
進場 → +60 pts → 回檔到 +20 → +120 pts → 回檔到 +50 → +200 pts → 趨勢延續 → +400 → 趨勢結束 → trail catches at +350
```

BE @ +60/+5：在「回檔到 +20」時就觸發 BE Floor（+5），把 +400 的大贏縮成 +5 的微贏（甚至 -1K 含滑價）。
SP @ +80/50%：在 +120 pts 時 SP_Floor = +60；回檔到 +50 時觸發 SP，把 +400 的大贏縮成 +60。

**結論：任何「持倉中段保護」對 L4 都有截斷大贏家的副作用。**
唯一不會截斷的 SP 設定是門檻極高（如 +200 pt），但這時只能保護極少數案例，整體效益不顯著。

## 五、1 筆夜盤殘留的解釋

**為什麼 Night_Block_On=true 還有 1 筆 02:00 進場？**

Path A 邏輯：
```powerlanguage
v_Night_Block = false;
if Night_Block_On = true and Time >= 200 and Time < 500 then
    v_Night_Block = true;
```

`Time` 是 K 棒收盤時間。15M 格線下：
- 01:45 收盤 → Time=145，**不在 200-500 區間**，block 不啟動
- 訊號於 01:45 收盤觸發 → 下一根 K 棒（02:00 開盤）成交
- **記錄的進場時間 = 02:00**

**這是「訊號時間」與「成交時間」的時差效應**，不是 bug。

**是否需要修正？**
- 殘留的 1 筆是 +22,200 贏家，**留著賺錢**
- 若改成封鎖「下一根成交在 02:00-05:00」，會多剔除一些 01:45 訊號（可能是贏家）
- **暫不修正**，B 已經是強勢勝利者

## 七、Path B 程式碼保留原因

雖然 BE/SP 實證失敗，**程式碼保留** 的原因：
1. 未來可能用更高門檻（如 SP @ +200/50%）再次測試
2. 可能配合「post-trail-only」改良（trail 啟動後才開 SP）
3. 移除程式碼會留下技術債（如未來想再做 A/B 需重寫）
4. Input 預設 0 = 完全關閉，無運行成本

**研究價值大於移除成本，所以保留。**

## 八、學到的新規則（記憶更新）

### 規則 1：100% 勝率的保護機制可以是淨損

**錯誤直覺**：CS_SP 22 筆 100% 勝率 = 完美機制。
**實證真相**：保護機制自己 100% 勝率不等於對策略有利，因為它截斷的 CS_SL 大尾巴贏家可能損失更大。

### 規則 2：多階段獲利策略不適合任何持倉中段保護

L4（Wyckoff Spring 反轉）、L1（趨勢追蹤）、L5（盤整突破）都可能有「進場 → MFE 達 X → 回檔 → 更大波段」的多階段模式。
- L1 用高門檻 SP（250 pts）+ 高 giveback（55%）成功，因為趨勢拉開後不易回檔到那麼低
- L4 用任何門檻都不行，因為反轉策略的多階段更頻繁
- **未來 L5 設計時不要直覺地套用 BE/SP**

### 規則 3：源頭過濾（Path A）優於中段保護（Path B）

進場品質過濾沒有截斷副作用，因為它剔除的是「不該進場」的訊號。
持倉中段保護必然有截斷副作用，必須極度謹慎。
