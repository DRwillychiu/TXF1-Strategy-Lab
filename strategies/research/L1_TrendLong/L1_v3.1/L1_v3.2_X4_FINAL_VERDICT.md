# L1 TrendLong V3.2 X4 Breakout Quality Filter — FINAL VERDICT

**Status**: KILLED (2026-07-25)
**Duration**: 1 session (~4 hours)
**Decision**: Revert to V3.1. X4 filter makes performance worse in MC12.

---

## What V3.2 tried to do

Add a "Breakout Quality Filter" using Data4 (1M) to score each breakout
signal before entry. Three features computed over a 45-minute observation
window (the current 45M bar's 1M data):

1. **Momentum**: Close of Data4 - Close of Data4[44] >= 0
2. **Flirtation**: count(High of Data4[idx] >= Breakout_Level, idx=0..44) >= 22
3. **Ascending Lows**: 9 bins x 5 bars, ascending transitions >= 4/8

Gate: Night (Time>=1500 or Time<500) requires score=3; Day requires score>=2.

## Root cause: Flirtation cliff-edge

MC12 debug output (488 potential entries, X4_Debug=True) revealed:

- 117 entries blocked. 105 are night session (90%).
- Of 95 Score=2 night blocks, **84 (88%) are missing only Flirtation**.
- Momentum ON rate: 96.3%. Ascending ON rate: 92.6%.
  **Flirtation ON rate: 60.9%** — it is the sole swing feature.
- Blocked entries have median Close-BO_Level gap of only 9.9 pts
  (vs 23.1 pts for passed entries). They hover near the threshold.

**Mechanism**: Flirtation counts `High of Data4[idx] >= Breakout_Level`.
Breakout_Level = MA61 + ATR20 * 2.0, computed on MC12's native 45M bars.
Python computes it via `resample('45min')` which has different bar boundaries.
A few points difference in BO_Level flips dozens of 1M bars across the
High >= BO_Level test, causing FlirtCnt to cross the >=22 threshold in
opposite directions. This is structural and unfixable — the two platforms
will never produce identical 45M bar boundaries.

## Evidence chain

1. PLA code implemented correctly (Python cross-validation: 282 vs 283
   trades, +3,900,200 vs +3,894,000 — 0.2% tolerance, 1-trade edge case)
2. ASCII verification: 30/30 PASS
3. MC12 backtest: 371 trades, +1,536,800, PF 1.323
4. MC12 debug output: 488 entries, 16-column CSV exported
5. Feature analysis confirms 88% of blocks caused by Flirtation alone
6. BO_Level gap analysis confirms marginal entries at cliff edge

## Why not fix it

- Lowering Flirtation threshold: curve-fitting, does not solve the
  structural bar-alignment mismatch
- Removing Flirtation, keeping 2-feature (Mom+Asc): Momentum=96.3% ON,
  Ascending=92.6% ON — both nearly always pass, filter becomes useless
- Using MC12-only indicators: would require re-doing all research inside
  MC12, losing the Python rapid-iteration advantage
- Any cross-timeframe feature (Data4 vs Data1) faces this same alignment
  problem

## Lessons

**L25**: Cross-timeframe features (Data4 1M evaluated against Data1 45M
indicators) are structurally fragile. Python resample and MC12 native bars
have different bar boundaries, making threshold-sensitive features like
Flirtation unreliable. Future entry filters should use single-timeframe
data only.

**L26**: A feature with >90% ON rate (Momentum 96.3%, Ascending 92.6%)
provides negligible filtering power. When 2 of 3 features are near-always
ON, the filter collapses to a single-feature gate — defeating the purpose
of a multi-feature scoring system.

**L27**: Python offline backtesting is reliable for single-timeframe
strategies (V3.1 SL_Pct worked perfectly) but unreliable for
cross-timeframe features where bar alignment matters.
