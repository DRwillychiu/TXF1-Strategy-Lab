# S2 Phase 2 初步分析 — 8 個重大發現

**分析日**：2026-06-17
**資料來源**：用戶 MC 12 跑 3 份可用 xlsx + 2 份 0 進場（v0.4 / v0.3）
**結論**：**v0.4 / v0.3 必須緊急修正才能繼續**，且發現 5 個獨立嚴重問題

---

## 三、致命問題詳細分析

### 問題 1：回測期間只有 3.5 年

**證據**：3 份 xlsx 設定 sheet 都顯示「開始日期 = 2022/07/11」

**可能原因**：
- MC 12 上 TXF1 30M 歷史資料只回溯到 2022/7
- 或 chart 設定 Bars Back 不足
- 或 Data2 (Daily) 對齊問題

**影響**：
- 沒涵蓋 2020 COVID 暴跌、2021 牛市、2022 熊市
- **樣本嚴重不足**（114-117 筆 / 3.5 年 = 33 筆/年）
- 統計信心降低

**修正動作**：
1. MC12 主畫面確認 TXF1 30M 資料下載到 2020 以前
2. Chart Settings → Bars Back: 設 5000+ 或 Custom Date Range: 2020/01/01
3. 重新跑回測

### 問題 2：原始資本 100,000

**證據**：「原始資本 | 100000」

**影響**：
- TXF1 一口保證金約 184,000
- 10 萬本金根本下不了 1 口
- 帳戶報酬 / MDD% 計算嚴重失真
- 「最大策略虧損 -315%」這種離譜數字就是這原因

**修正動作**：
1. Format Strategy → Properties → Capitalization
2. Initial Capital: 改為 **1,000,000**
3. 重新跑回測

### 問題 3：v0.3 / v0.4 完全 0 進場

**證據**：用戶回報「完全沒有數據資料」+ v0.2 vs v0.3 唯一差別是 B+C 系列

**邏輯推斷**：
```
v0.2 (B+C 全 off, A 全 off): 114 進場 ✓
v0.3 (B+C 全 on, A 全 off): 0 進場 ✗
v0.4 (A+B+C 全 on): 0 進場 ✗

v0.2 → v0.3 唯一新增的進場過濾：
  - B-2: ConfirmBars(2) 連續站穩
  - B-3: VolFilter (Volume > MA × 1.2)

C 系列（BE/Trail/SP）只影響出場，不影響進場
A 系列在 v0.3 仍關閉，所以 v0.3 = 0 完全是 B 系列造成
```

**最可能元兇**：**B-3 VolFilter**

理由：
1. MC 12 TXF1 30M Volume 在某些情況下可能顯示 0 或無效
2. 即使有 Volume，1.2× MA 是相對嚴格門檻
3. 若 `Average(Volume, 20) = 0` → `v_VolPass = false` 永遠
4. ConfirmBars(2) 雖嚴但歷史上 Inside Bar 突破後總有一些連續站穩的案例

**次可能元兇**：**B-2 ConfirmBars(2)**

如果 Inside Bar 後的突破總是「突破當根後立刻反向」，那 2 根連續站穩可能很少發生。

**驗證方法**（用戶執行）：
```
跑 v0.3-A：只開 Confirm_On=true, VolFilter_On=false  → 看樣本數
跑 v0.3-B：Confirm_On=false, VolFilter_On=true       → 看樣本數

若 v0.3-A 有樣本、v0.3-B = 0 → 元兇是 VolFilter
若 v0.3-A = 0、v0.3-B 有樣本 → 元兇是 ConfirmBars
若兩者都 = 0 → 兩者各自都過濾過度
```

## 四、嚴重問題詳細分析

### 問題 4：整體 alpha 為負

**證據**：
- Naive PF -0.90（淨利 -148K）
- v0.2 PF -0.79（淨利 -325K）
- 兩個版本都虧錢

**含義**：
- **教科書版母子線突破策略在 TXF1 30M 上不賺錢**
- 這驗證了 E-1「alpha 已被市場消化」的擔憂
- 我之前說「殘餘 alpha 可期」**過於樂觀**

**但有救嗎？**
- Long 子集 PF 1.17-1.26 → **Long-only 可能有勉強 alpha**
- 加 A 系列過濾（如能解決 0 進場）可能提升 PF

### 問題 5：Long vs Short 嚴重不對稱

| 版本 | Long PF | Short PF |
|------|--------|---------|
| Naive | 1.26 ✓ | 0.34 ✗ |
| v0.2 | 1.17 ⚠️ | 0.23 ✗ |

**含義**：
- **空單完全沒 alpha** — PF < 0.5 = 大虧
- 解決方案：**砍掉 Short 邏輯，做 Long-only**
- 對照憲法 H-1 預判（雙向 alpha 不對稱）→ **完全證實**

**預期效果**：
- 拿掉空單 → Naive PF 從 -0.90 拉到約 +1.26 = **轉虧為盈**！
- v0.2 Long-only 預期 PF +1.17 = 勉強賺

### 問題 6：同一天連續多筆進場

**證據**：
```
#2 進入 Long 2022-08-09 12:15 @15055
#3 進入 Long 2022-08-09 12:45 @15035   ← 同一天 30 分鐘後又進
#116 進入 Long 2026-01-28 10:45 @32730
#117 進入 Long 2026-01-28 11:15 @32717  ← 同一天 30 分鐘後又進
```

**可能原因**：
- 第 #2 筆 12:15 進場後 → 立刻 SL 出場（短時間內）
- MarketPosition 變 0 → 12:45 又符合條件 → 再進場
- v_Prev_MP 在 MarketPosition=0 時的判定可能允許「同一根 K 內反復進出」

**問題**：
- 一天進場 2 次 = 風險翻倍
- 同一天兩筆都用相同 Inside Bar 訊號（昨日母子線）= **重複 alpha 浪費**

**修正方向**：
- 加入「每根 Inside Bar 訊號只進一次」邏輯
- 或加「每日最多 N 次進場」限制
- 或加「進場後 N 根 K 不再進場」cooldown

### 問題 7-8：用戶操作小錯誤

#### 7. Naive_offset5 vs offset0 是同一份

- 兩份檔案 hash 不同（用戶確實重跑）
- 但進場數 / 績效完全相同
- 原因：兩者 BreakOffset_Mode 都不等於 1，都走 else 分支用 BreakOffset(5)
  - offset5: BreakOffset_Mode = 5（非 1，走 else）
  - offset0: BreakOffset_Mode = False = 0（非 1，走 else）

#### 8. BreakOffset_Mode 輸入值錯

- 應該輸入 0（固定）或 1（動態）
- 用戶輸入：5 / False / 1
- MC 12 把 5 顯示為「5」，把 False 顯示為「False」
- 程式邏輯上：只有 = 1 才動態，其他都當 0


### 路徑 B：激進修正（P0 + P1 + Long-only）

```

3. 修正同日多進場 bug
4. 找 B 元兇修正
5. 重跑全部 4-5 個版本
```

我建議**路徑 B**，因為 Short PF 0.23 是明確負面證據。

## 七、要不要繼續做 S2？

### 三種可能結局

#### 情境 1：修正後 Long-only PF > 1.5
→ **alpha 確實存在**，繼續 Phase 3 嚴謹驗證

#### 情境 2：修正後 Long-only PF 1.0-1.5
→ **勉強有 edge**，但需要更多優化才值得上架

#### 情境 3：修正後 Long-only PF < 1.0
→ **alpha 確實已被消化**，誠實 archive

### 我的判斷

從 Naive Long PF 1.26 (3.5 年, 87 筆) 看：
- **有殘餘 alpha 但極弱**
- 加上 A+B 過濾**可能**提升到 1.5+
- 但若過濾過度導致 0 進場（如 v0.4）= 無用

**保守預期**：修正後 PF 1.2-1.8，**邊緣可用但不強**。

## 九、誠實檢討

我這次的設計又有失誤：
- 我設定 ConfirmBars(2) 預設為「連續 2 根 K 站穩」，**沒考慮歷史資料中這條件是否能滿足**
- 我設定 VolMultiplier(1.2) 預設「Volume > MA × 1.2」，**沒驗證 TXF1 30M Volume 在 MC 是否可用**
- 結果 v0.3 / v0.4 完全 0 進場 = **設計過度激進**

**根本原因**：我沒有對 MC 環境的 Volume / Confirm 行為做實證。再次「設計超前實證」。

**修正方向**：未來新增「過濾類 input」必須在 MC 上先測「會剩多少進場」，再決定預設值。
